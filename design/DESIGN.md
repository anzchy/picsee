# picsee Design System — Quiet Image Canvas

更新：2026-10-21。**本文件是 picsee 当前 C 方案的主设计规范。** 产品是原生 macOS 本地看图软件，目标架构为 Swift + SwiftUI + AppKit。浏览器原型与 HTML 状态稿用于验证设计，不是原生应用实现。

## 1. 权威来源与验证边界

- 设计规则以本文件及用户明确决定为准；开发阶段与范围以 [开发计划](../docs/PICSEE_DEVELOPMENT_PLAN.md) 为准，原生状态/图像管线以 [架构](../docs/PICSEE_ARCHITECTURE.md) 为准。
- Token 的运行时实值在 `picsee-ui-system/tokens/{globals,light,dark}.css`；组件契约在 `picsee-ui-system/components/`。下表只是语义摘要，调整后须同步导出。
- 原生实施输入见 [组件与原生映射](picsee-ui-system/native/README.md)：限定原生角色白名单、组件输入/状态、SwiftUI/AppKit归属及P0-08验收。Web三个primitive的代码不代表已有原生组件。
- [当前交互原型](prototypes/picsee-browser/viewer-v2.html) 验证 Space、翻图、Esc、主题和已有面板等交互；其初版与 revisions 仅是 picsee 演进记录。
- [本地设计索引](prototypes/picsee-browser/states/index.html) 包含20个界面/状态稿，详细状态以 `manifest.json` 为准。31–34 是本地补充稿；原云端来源以状态稿目录的 `provenance/stitch.json` 和收据为准，重新打包不等于已同步云端。
- 静态稿中的按钮、菜单、选择态不代表功能已实现。原生窗口、VoiceOver、权限、真实文件操作及性能必须另行实机验收。
- mdpro 只保留视觉来源归属，不继承其 Markdown 产品布局、ADR、规则优先级或历史对比度豁免。来源见 [IMPORT.md](IMPORT.md)。

## 2. 产品方向与非目标

照片是主要内容，应用界面负责目录定位、选择、翻图和检查。采用冷静中性色、一个蓝色交互强调色、细分隔线、平面导航行和有限阴影。

不增加营销首屏、账号头像、云相册、画板、永久批量工具横栏、装饰渐变或玻璃侧栏。首次打开的 B4 散落相纸（边缘半透明样图、中央拖入区，2026-10-27 用户定稿，见计划 P3-16）不算营销首屏：它只在没有打开过文件夹时出现，主操作仍是选择或拖入文件夹。不引入 Source/WYSIWYG、TOC、编辑器标签页等其他产品结构。保持现有照片身份，不把其他软件截图当作照片缩略图。

批量导出/删除闭环、壁纸、复杂资产管理和常驻鹰眼不能因出现一张生成稿就自动进入产品范围。导航图按开发计划 P4-06 评估，默认按需出现。

## 3. C 布局与工具分工

### 网格

- 顶部只保留紧凑原生风格窗口区域和当前目录名。38px 是浏览器原型的参考值，原生系统标题栏以 AppKit 实际行为为准。
- 缩略图从标题区域下方直接开始，外边距16–24px；不恢复面包屑、文件夹大标题或常驻搜索横栏。
- 文件夹侧栏可收起、可调整宽度；原型约196–220px，设置范围160–320px。应为主要内容保留合理宽度。
- 底栏约40px。窗口最左下固定侧栏开关；左侧显示当前文件/选择数量；右侧为搜索、排序、信息、显示设置。
- 主题、密度、文件名显示、缩略图裁剪方式、工具常驻和帮助收进显示菜单。搜索生效后始终能找到清除入口。

### 大图

- 图片画布占满可用区域，不设应用顶部工具横栏。适应窗口保留约16px边距，保持长宽比，默认不放大小图。
- 左下：侧栏、返回网格、更多。中下：前后翻图、文件名、序号。右下：缩放与适应/原始尺寸。
- 工具叠放在画布上，默认静止约2.5秒隐藏；该时长是可调整的原型参数。边缘/Tab 可唤回，提供始终显示偏好。
- 菜单、Inspector、胶片条展开及键盘操作控件期间暂停隐藏。隐藏控件必须不可点击、不可聚焦、退出辅助技术树；不能只设 opacity:0。
- 原生普通窗口必须保留可靠的关闭、最小化、全屏与拖动方式。窗口拖动与放大图像的平移手势分离。

### Filmstrip

- 默认收起，记住用户选择；展开时不额外缩小主图，不增加顶部信息条。
- 胶片条整合文件名、序号及前后按钮；移除另一套中部翻图组。左下入口与右下缩放保持，窄窗时不碰撞。
- 当前缩略图可定位、可滚入可见范围；大量项目使用有界加载/虚拟化，而不是一次解码整目录。

### 菜单与 Inspector

- 图片右键菜单优先提供快速查看、在访达中显示、拷贝路径、收藏、图片信息；操作按上下文可用性决定。
- 目录菜单与图片/多选菜单分开定义。删除和导出进入对应开发阶段后再补错误、恢复和撤销边界。
- Inspector 在侧面按需展开，不占用图片上方横栏；浅深主题共用几何结构和语义 token。

## 4. 视觉 Token

| 语义角色 | 浅色 | 深色 |
| --- | --- | --- |
| 画布背景 `--color-bg` | #ffffff | #0f1115 |
| 侧栏/安静表面 `--color-surface` | #f6f7fb | #161a22 |
| 浮层 `--color-panel` | #ffffff | #141821 |
| 主要文字 `--color-text` | #1a1a1a | #e5e7eb |
| 次要文字 `--color-muted` | #6b7280 | #9aa4b2 |
| 强调/焦点 `--color-accent` | #2563eb | #60a5fa |
| 实色动作 `--color-accent-fill` | #2563eb | #1d4ed8 |
| 实色动作文字 `--color-on-accent` | #ffffff | #ffffff |
| 错误文字 `--color-error-text` | #b91c1c | #f87171 |

分隔线由文字色与透明度派生；装饰分隔线不能代替重要控件边界。背景与图片分离，主题切换不改变照片本身的色彩。

字体使用 SF Pro Text / 系统 sans，数值和快捷键使用 SF Mono / 系统 monospace。常规字号12/13/14/16px；必要信息不低于12px。字号下限是产品取舍，并不单独证明可访问性。

基础间距4px，常用8/12/16/24px。内部圆角4px、控件6px、浮层10px。只使用语义 token；弹出菜单/工具浮层使用一个克制的阴影，不给每张照片添加阴影卡片。

采用同一套轮廓图标，常见图形16–18px；图形尺寸与点击区域分开。强调色用于交互状态，不用发光、毛玻璃或色彩数量表达“原生感”。

## 5. 组件和状态契约

- **IconButton**：有可访问名称；default/hover/pressed/focus/disabled 区分。紧凑桌面目标通常28–32px，不能以缩小点击区域换视觉简洁。
- **NavRow**：平面目录行、图标、截断名称、可选计数；选择使用弱强调色，不改变布局尺寸。名称可获得完整文本。
- **缩略图**：单选为细蓝边框及弱文件名底色，不叠加整卡蓝底和圆形勾选。多选可显示小勾选标记；选择集合、当前项、键盘焦点是不同状态。
- **文件名**：默认一行；只看图片模式可隐藏。图片说明不作为第二行常驻内容。
- **缩略图模式**：完整适应与裁剪预览明确可选；裁剪预览不用于判断完整构图。
- **元数据**：仅展示真实读数；缺失值使用“—”或明确不可读状态，不编造 ISO、焦距、RAW、总大小、文件数量或进度。
- **搜索**：明确范围和当前筛选；空结果给出清除搜索。输入焦点期间箭头/Space 不触发全局翻图。
- **菜单**：按需出现，尺寸不越出窗口；Esc 优先关闭并恢复触发处焦点。键盘可操作，不能只有鼠标右键路径。
- **空态/加载/错误**：简短说明＋相关下一步；保持目录和文件上下文。未获得总数时使用不定进度，不伪造百分比。
- **1:1**：按源图像素对显示 backing pixel 定义，不把适应窗口倍率当成真实百分比。平移使用 grab/grabbing 等可辨识状态，并限制边界。

## 6. 键盘与焦点

| 命令 | 当前设计约定 |
| --- | --- |
| Space | 打开/关闭大图；输入/菜单等上下文先消费按键 |
| ← / → | 大图前后翻图；网格移动当前项 |
| ↑ / ↓ | 网格按行移动 |
| Enter | 打开选中图片 |
| Esc | 先关闭当前菜单/弹出层，再返回网格；保留选择和滚动位置 |
| 0 / 1 | 适应窗口 / 原始尺寸 |
| + / − | 放大 / 缩小 |
| ⌘F | 网格内打开搜索 |
| Tab | 可见焦点；唤回隐藏工具 |

多选设计采用 macOS 修饰键语义：⌘切换单项、Shift 范围选择；必须维护选择锚点和当前项。多选后 Space 预览选中集合还是整个目录仍需在实现前确定，静态32页不代表已经实现。

⌘O、⌘I、Trash 等尚未落实的命令不能随意画进每页快捷键提示。整个应用使用同一命令表；Space 不另外分配为平移开关。菜单、文本输入、裁剪等上下文具有优先级。

Web 原型优先用原生 button/input/select。多项图片可采用 listbox/option 与 aria-selected；如果每项包含独立交互控件，应评估 grid 模式，避免在 option 内塞入一组独立按钮。复合控件采用可控焦点策略，避免每张图片都成为 Tab 停靠点。

原生实现用 AppKit/SwiftUI 的可访问性语义和命令路由，不照搬 DOM/ARIA 作为原生验证证据。

## 7. 前端实现与可访问性验收目标

这些是新的验收目标，**不是当前20份稿已通过 WCAG 或 VoiceOver 的声明**。

1. 正常大小文字以4.5:1为最低目标；符合标准定义的大文字以3:1为目标。必要控件图形、边界和状态以相邻色3:1为目标，按真实合成背景测量。不可将 mdpro 的历史豁免直接迁入。
2. 不只用颜色表达选择/错误；保留语义、形状、文字或状态属性。禁用态与可用态可区分，必要信息不能靠降低不透明度隐藏。
3. 自定义指针目标以至少24×24 CSS px为基线，或逐项核对标准的间距等例外；本产品优先28–32px桌面目标。小图标并不意味着小点击区域。
4. 键盘焦点始终可见，不能被底栏/胶片条完全遮挡；项目目标是完整可见。弹层关闭后回到合理触发位置，不遗落在已隐藏控件上。
5. 隐藏工具使用 visibility/inert/可访问性状态配合；移除 inert 后才能转移焦点。模态对话框正确管理进入、循环和恢复焦点，非模态 Inspector 不无故锁住焦点。
6. 遵循 prefers-reduced-motion；主题颜色即时切换，短动效只服务于显隐和反馈。不要把动画作为发现功能的唯一提示。
7. 使用 CSS Grid/Flex 的 min-width:0、边界限制和稳定图片比例；避免导出时固定1280px后冒充响应式。参考1280×800、1019×853、紧凑800×680分别检查。
8. 长中英文件名、竖图、透明图、0/1/大量图片、加载与错误场景都要覆盖。保留完整名称访问方式，不能仅靠 hover 提供关键内容。
9. 大目录需虚拟化/有界加载，按 viewport 生成缩略图，避免滚动时大量解码；解码取消与缓存策略遵循架构文档。静态稿嵌入照片不作为性能实现方案。
10. 文件名、路径和元数据作为不可信文本处理；不要直接注入任意 HTML。网页导出不执行本地素材附带脚本。

标准依据：W3C [文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[目标大小](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)、[键盘界面](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)、[Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)。WCAG 用于 Web 原型的基线；原生可访问性需额外实机检查。

## 8. 设计交付与变更纪律

- 同一控件在浅深主题、窗口尺寸和交互状态间保持结构一致；共享 token 和组件，避免每页自行发明一套工具栏。
- Stitch 生成稿是候选。新增图必须核对照片、文案、数据和 C 布局，不能凭“生成成功”升级为正式稿。
- 本地新增、云端已上传、交互已实现、原生已验收分别记录；不能混为“完成”。
- 静态导出只修改目标 DOM 的 class/属性，不对整份 HTML 全局替换状态词，避免误改 CSS 选择器。隐藏页与显示页必须做差异断言。
- 每次设计修改都检查资源链接、图片加载、布局溢出和受影响状态。CSS 语法检查、截图检查、键盘行为测试和真实设备测试属于不同证据。
- 本地20页中的选择/右键/浅色 Inspector 等静态补充仍需交互实现；完整对比度、200%文字缩放及 VoiceOver 尚未完成整体验收。
- 更新本文件后同步设计系统说明；需要Stitch导出时生成本地忽略的 `.stitch/DESIGN.md`；云端同步必须有明确任务授权及实际收据，不默认宣称已更新。
