# picsee 分阶段开发计划

更新：2026-10-28 · 版本：v0.5 · 状态以[功能账簿](./feature-ledger.md)为准（账簿无 Shipped）。v0.0.1 内部按用户旅程推进（[ADR-013](adr/0013-build-by-user-journey-slices.md)，§1.6、§14）。剩余任务见 §14。

技术路线：**Swift + SwiftUI + AppKit**。先阅读 [架构设计](./PICSEE_ARCHITECTURE.md)；功能依据为 Picview 功能清单 `docs/PICVIEW_FEATURES.md` 与技术分析 `docs/PICVIEW_ANALYSIS.md`（本地研究资料，不在公开仓库）。本计划不表示任何原生阶段已验收通过：实际有什么以[功能账簿](./feature-ledger.md)为准，真机记录在 `docs/validation/P*.md`。原生工程已由 P0-01 建立（`project.yml` + `Packages/PicseeKit`）。

设计依据按顺序为：用户确认的 **C · Quiet Image Canvas**、[主设计规范](../design/DESIGN.md)、[20页本地 mockup 索引](../design/prototypes/picsee-browser/states/index.html)与[本地补充说明](design/C_LAYOUT_ADDITIONS.md)。Stitch 云端未采纳的07/08等探索稿不作为实现基线。原生代码不打包 HTML/CSS 或 Stitch/REA/npm 运行时。

## 1. 交付顺序与范围

```text
P0 技术验证、设计映射与命令底座
 → P1 单图打开、C 沉浸画布与加载
 → P2 文件夹连续浏览、授权与可选 Filmstrip
 → P3 C 网格、多选/菜单/基础信息、缓存与性能收敛    ← 日常使用 MVP（v0.0.1）
      （v0.0.1 内部：J1 → J2 →（J1/J2 真机记录后）J3、J4，见 §1.6、§14）
 → P4 桌面窗口、置顶、交互与幻灯片
 → P5 元数据、标签、基础编辑与导出
 → P6 兼容、可访问性与发布         ← 首发 v1
 → P7 OCR、RAW/HDR/Finder 等增强   ← 按实测与需求逐项加入
```

每阶段以**可演示行为 + 验证记录**为完成条件，上一阶段的关键门槛未通过，不靠新增功能掩盖问题。首发不以“与 Picview 所有设置逐项一致”为目标。

阶段（P0–P7）是范围目录，工作包编号不变；排期顺序按用户旅程（§1.6、§14.2～14.6）。各工作包的复选框不勾选，完成状态以账簿和 §14.1 为准。

### 1.2 工作量的使用方式

采用“一个熟悉 Swift 基础的开发者、顺序推进、核心时间投入”的**粗估有效工程日**，不包含等待证书、用户反馈、素材授权和平台审核。这里没有实际开发速度数据，初始估计仅用于比较工作量；P0/P1 完成后必须用实际记录重新估算。

| 阶段 | 粗估 | 可独立使用的成果 |
|---|---:|---|
| P0 | 3–5 日 | 工程底座、原生设计映射、命令与风险记录 |
| P1 | 5–8 日 | 稳定的 C 沉浸单图查看器 |

### 1.4 最小状态模型与实施前冻结点

以下默认行为已在 2026-10-21 grilling 中由用户确认冻结（仍不是已实现的事实）。P0-09/P3-09开始时记录为命令/状态表；如变更须同步 DESIGN.md、用例及验收，不由每张 mockup 自行决定。

- `BrowserSelection` 持有 `selectedItemIDs`、`currentItemID`、`anchorItemID`；图片身份不使用索引代替。切换过滤/目录/排序时与对应快照版本协调。
- **Space 预览范围（用户已确认，2026-10-21 grilling）**：只选1项时按当前过滤/排序后的目录序列翻图；多于1项时按同一排序后的选中集合翻图。Viewer保存来源快照版本和有序ID集合；Esc恢复原选择集合、当前项和滚动锚点。遇删除/权限变化按已冻结序列核对移除，不悄悄扩大到全部目录。
- ⌘切换单项、Shift以锚点做范围选择；方向键/修饰键和焦点联动在原生 NSCollectionView 中验证并固化，不能仅凭静态蓝框判定完成。
- `ViewerChromeState` 显式描述隐藏、可见、用户常驻及交互锁定；菜单/Inspector/Filmstrip/键盘焦点形成保持可见条件。用可控时钟验证约2.5秒，不靠散落定时器或字符串替换。
- `DisplayPreferences` 保存外观、侧栏/宽度、Filmstrip、文件名、缩略图适应方式/尺寸、工具常驻，以及排序（字段与升降序，App 级、所有窗口与文件夹共用、跨启动保留）。扩展名过滤属于某窗口里的某个文件夹：同一文件夹重扫（递归开关、Retry、重新授权）保留，打开其他文件夹或重启时清空。搜索词是瞬时过滤，不跨启动恢复，不与布局偏好混存（2026-10-25 grilling）。
- 打开文件夹落在网格：扫描中显示读取状态，完成后出完整网格，排序首张为当前项、无选择；Space/Enter 进大图，无选择时预览集合为整个文件夹、从当前项开始。以单图打开时直接进大图，若其文件夹在授权根内，Esc 先显示读取状态（尚未扫描时），再回该文件夹网格且当前项为这张图（被过滤或已不在时退回排序首张）（ADR-0010）。
- 原生基础命令从P0建立：Space、箭头、Esc、Enter、0/1、+/−、⌘F；⌘O 对应可选文件/目录的“打开…”，⌘I 显示/隐藏基础 Inspector。阶段尚未实现时不展示已可用的快捷键提示。
- 图片右键动作采用不可变目标身份/快照，避免菜单打开后当前项改变导致作用到别图。多选菜单仅开放已实现且语义明确的集合操作；基础多选不自动授权批量导出/删除。

| S1 | 50 张 1–12MP JPEG/PNG/HEIC，含透明与 EXIF 方向 | 正确显示、颜色/方向、菜单操作 |

### 10.2 初始工程目标，P0 校准后作为门槛

| 指标 | 初始目标与测量边界 |
|---|---|
| 命令反馈 | 导航/缩放输入到状态反馈 p95 ≤ 100 ms；不等于像素已完成解码 |
| 普通图首个可用预览 | S1、本地 SSD、冷应用缓存 p95 ≤ 500 ms；RAW/PDF/S3 单独报告 |
| 热内存翻图 | 有相应尺寸像素命中的场景，输入到呈现 p95 ≤ 100 ms |
| 目录首张 | 打开文件夹：单层扫描完成并显示完整网格（排序首张为当前项）的时间（ADR-0010），S2 扁平副本本地 SSD 待测定（目标 ≤ 1 s）；以图片打开：该图显示时间；扫描完成单独记录 |
| 目录一致性 | 停止写入后普通小批变更 2 s 内核对完成；重扫/慢卷显示进度并另测 |
| 图形交互 | 60 Hz 基准下记录 frame/hitch；连续缩放与滚动不得出现可复现的长时间主线程解码阻塞 |
| 资源有界 | 全局 worker/队列/缓存不超过配置；反复浏览同一素材三轮后不持续线性增长；返回空闲状态记录 retained objects 与 RSS，不要求系统立即归还全部 RSS |
| 磁盘缓存 | 写入/淘汰收敛后不高于配置高水位；异常断电/坏索引后可重建，不影响原文件 |

时延指标每类至少 30 次采样，记录 p50/p95 与极值；小样本不足不写“通过 p95”。性能未达标时记录 bottleneck、取舍和新的验证，不能直接放宽目标后删除原结果。
