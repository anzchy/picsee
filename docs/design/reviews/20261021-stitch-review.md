日期：2026-10-21。本轮为只读复核：读取云端清单及新稿 HTML/截图、比对旧操作收据，检查本地原型；未改动设计稿、未上传或生成新页。

## 结论

建议部分属实，但混合了三种不同问题：尚缺的交互设计、已有功能缺少独立状态稿，以及额外功能/视觉偏好。最新云端已有五份对应新稿，不能继续把这五个方向统称为“缺页”。新增稿仍须按已确认的 C 布局验收，生成出来不等于通过设计评审。

## 二、逐项核对 Gemini 的说法

| Gemini 说法 | 核对结论 | 实际边界 |
| --- | --- | --- |
| 缺少与浅色对等的深色精修页 | 部分属实，且最新已补出 09 | 11/12 原本已有成对的浅深色 HTML 基线；07 是此前未通过的生成探索，不是已批准的新基准。不能先把 07 定为高保真标准再判 12 不合格。09 已存在但仍有明显偏离。 |
| 多选/批量操作状态缺失 | 对此前原型基本属实 | 当前原型使用单个 selected ID；新稿补了多选视觉。⌘单击、Shift 连选、全选、当前项/焦点分离、Space 预览选中集合还是当前目录，仍需明确。批量导出与资产管理不是多选边框自然附带的既定范围。 |
| 右键菜单缺失 | 基本属实 | 原型未实现图片/文件夹上下文菜单；新稿补了图片菜单。文件夹菜单、空白区菜单、多选菜单与不可用项仍需定义。 |
| Filmstrip 缺失 | 缺的是此前的独立设计稿，不是功能 | 本轮在原型浏览器中实际展开了 12 张缩略图；代码已有开关、选中项定位和偏好保存。最新云端已有展开态。必须保留“默认关闭、用户主动展开”的决定。 |
| 1:1 裁切和平移缺失 | 不属实；导航图设计可补充 | 原型已有真实倍率计算、grab/grabbing 与边界受限平移，27 已有静态稿。开发计划 P4-06 也列了缩略导航图。鹰眼可作为该阶段的设计补充，不是所有看图器或 MVP 必须常驻的部件。 |
| 大图左下侧栏/回网格可以合并 | 属于待决策建议，不是已证实缺陷 | 两者职责不同：一个控制文件夹树，一个退出单图；且用户此前明确要求侧栏开关在左下。可优化标签和解释，但不应未经确认删掉入口。 |
| 浅色 Inspector 缺少对齐 | 缺少独立状态稿的判断成立，缺少主题能力不成立 | 本轮切到浅色并打开 Inspector，实际背景为 rgb(255,255,255)，因为组件使用主题 token。仍建议补一份浅色 Inspector 稿和主题对照。 |
| 空态留白过多，应该加快捷键 | 视觉判断，不是缺陷结论 | 留白符合安静画布；可以改善说明与层级，但不应为了填空加装饰。原型目前没有实现 ⌘O 打开目录，若加徽标必须同时定义命令语义与后续实现，避免暗示已可使用。 |

“深色更适合摄影师”“AppKit 质感”“底栏毛玻璃”“发光边框”等是设计取向，不是现有验收规则。规范目前采用中性、不透明的底栏、细边框和单一蓝色焦点，不要求发光或毛玻璃；尤其不应恢复玻璃侧栏。

## 三、五份新增稿的实际问题

| 新稿 | 可以保留的方向 | 本轮发现的偏离 |
| --- | --- | --- |
| 09 深色网格 | 独立深色对照页 | 画面出现外层浅色应用壳与内层深色应用的双侧栏/双窗口结构；不等同 11 的深色对等版。 |
| 批量多选 | 多项选中视觉、选中数量与命令分组 | 新增了顶部文件夹说明/批量操作区；部分缩略图内嵌了界面截图片段；出现未验证的文件大小和 EXIF；与已删掉顶部 banner 的决定不一致。 |
| 右键上下文菜单 | 在照片附近按需出现菜单，不占常驻空间 | 菜单里“设为壁纸”等尚未按产品阶段确认；图片、目录、多选命令仍须分开。不能仅凭菜单文本认定功能已完成。 |
| Filmstrip 展开态 | 底部轻量缩略轴、当前项标记 | 主图相对画布明显缩小；加入额外顶部相机信息和全局状态条。应优先恢复图片占比，避免给缩略轴再配一套管理界面。 |
| 鹰眼导航 | 在图片超出视口时帮助定位 | 额外提示条、工具列和元数据增加干扰；常驻导航窗不是已批准要求；应仅在放大/平移时按需出现并与原图视口准确对应。 |

五页共有的问题：新增“未命名图库 / 画板 / 相册 / 废纸篓 / 个人头像”等导航；这不是本地目录看图器的既定信息架构。外层状态栏又写“324 项文件已载入”，而画面和序号只有 12 张，示例内容不一致。

### 必须先解决的语义冲突

1. 多选稿将“移至废纸篓”标作 ⌘D，右键稿标作 ⌘⌫，两稿互相冲突；应由统一命令表决定，不由每页生成器自由编造。
2. 鹰眼稿写“空格键快捷切换平移”，而已确认的 Space 语义是打开/关闭大图。当前原型在 keydown 就切换模式，不能直接叠加这条说明。
3. 鹰眼/多选/胶片稿填入 6000×4000、ISO 100、35mm、RAW 等参数；真实示例鸟居图为 1600×2400 JPEG，未提供这些 EXIF。应显示真实字段或明确占位，不能当作已验证信息。
4. 开发计划将复制路径、分享、Trash 与导出列在 P5，且明确不纳入批量资产管理。可以先设计基础多选，但批量导出、批量删除的失败/撤销闭环需另行定范围。

## 四、建议的下一步顺序

1. 先清理五份新稿的共同外层壳、顶栏和假数据，保留 C 布局；09 直接对齐已批准的 11/12，而非旧 07 探索稿。
2. 优先接纳“图片右键菜单＋可选 Filmstrip”的设计方向，补清命令语义及展开/关闭/当前项关系。
3. 多选先定义选择集合、焦点、预览集合与键盘规则，再讨论批量业务；不把所有资源管理功能一并塞入。
4. 鹰眼按 P4-06 做可选定位辅助，避免常驻挤占画布；不改变 Space 的既定含义。
5. 真正仍值得补的稿：浅色 Inspector、文件夹上下文菜单、多选的 Shift 范围选择/无选择/混合结果；如决定做 Trash/导出，再补确认、失败和恢复状态。

以上是复核建议，不代表自动采纳或已修改页面。
