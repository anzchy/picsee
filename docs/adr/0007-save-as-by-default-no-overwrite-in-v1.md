# ADR-007：编辑默认另存为新文件，首发不要求覆盖原文件

旋转、翻转、裁剪保存为非破坏的 `EditRecipe`，预览与导出共用变换逻辑，UndoManager 支持撤销；首发的输出方式是**另存** JPEG/PNG，明确输出尺寸、质量、色彩与 metadata 策略（架构 §7.3；开发计划 P5-03、P5-04）。覆盖原文件属于后续写入能力：需要重查源修订、检查授权、临时写入、协调与替换，外部修改产生冲突时另存而不静默覆盖（架构 §7.3）。首发只对静态图片编辑；GIF 动画、PDF、RAW 的写回不属于 v1（开发计划 P5）。

这样选，是为了把「误覆盖用户原图」这种不可逆风险与基础浏览、基础编辑解耦：另存失败最多是导出失败，原文件不会被改动（开发计划 P5 验收「另存失败不修改原文件」）。picsee 以文件系统为真相源（[ADR-004](./0004-filesystem-source-of-truth-versioned-snapshots.md)），用户的原图就是唯一的原件，不应由一个尚未完成冲突检测的写入路径去替换它。

## Considered Options

- **首发支持原地覆盖**：符合部分用户习惯，但需要原子替换、外部修改冲突检测和多窗口一致性，全部进入首发关键路径。未选，推迟。
- **只做非破坏 sidecar（编辑参数另存，不导出像素）**：不碰原图，但其他应用看不到编辑结果，且引入额外的持久文件。未选。

## Consequences

- P5-04 默认另存；P5-07 处理未保存编辑在切图、关窗、外部变化时的提示（账簿 EDIT-03、EDIT-06）。选择去除 metadata 时要验证不残留 GPS/IPTC（架构 §7.3）。
- 导出目标已存在或源修订变化时，给冲突提示或另存，不丢源文件、不把失败标成成功（架构 §8 场景表 `exportConflict`）。
- 覆盖原文件另开后续工作包，前置条件是冲突检测与原子替换验证（开发计划 P5）。
- v1 **不提供覆盖原文件**（用户决定（2026-10-22））；架构 §7.3「首发允许推迟」按此改为「首发不提供」。
- 保存面板中选中一个已存在的**其他**文件时，经系统的替换确认后允许替换；源文件本身仍不能作为保存目标（用户决定（2026-10-22））。
  - 「源文件」按 `ItemID`（卷标识与文件资源标识）判断，不按路径，硬链接、别名和大小写不同的路径都算源文件；保存面板在用户确认前拒绝这个选择（例如经 `panel(_:validate:)`），并说明原因。
  - 替换已存在的其他文件也是事务式的：先写到同一卷的临时文件，成功后再原子替换；编码失败、磁盘满、用户取消时，旧的目标文件保持完整。这些情况列入 P5-04 / EDIT-03 的验收。
- v1 的编辑参数（EditRecipe）**不跨关窗或重启保留**；关窗前未保存的编辑按 P5-07 提示（用户决定（2026-10-22））。
- 重评条件：编辑需求成熟、覆盖路径的冲突检测与原子替换测试通过后（架构 §10）。
