### 日志 subsystem 与 category

统一使用 `io.github.anzchy.picsee`。目前已实现的只有 `lifecycle` 的启动身份日志
`Picsee launch git=<sha>`；下表其他 category / signpost 是后续工作包要采用的约定，**不是已发出事件**。

| category | 用途 |
|---|---|
| `lifecycle` | 启动 / 退出、构建 SHA；与真机 doctor 的运行身份核对 |
| `command` | 输入接收、路由到状态反馈；不记录用户输入的搜索文本 |
| `render` | 首个可用像素呈现、内存命中呈现、frame / hitch |
| `decode` | 排队、实际解码、结束 / 失败 / 取消，实际解码字节数 |
| `filesystem` | 扫描首批 / 完成、增量核对；授权后的相对素材标识 |
| `access` | File Grant / Access Root 的租约开始与配平释放；不把最近记录当作授权 |
| `cache` | 命中层级、缓存字节、高水位与淘汰收敛；无磁盘缓存实现时不伪造事件 |
| `performance` | worker / queue / cache / RSS / retained objects 的实测快照与运行条件 |

### §10 度量边界与 signpost 名称

同一操作用独立 signpost ID 关联 begin / end；多窗口、并发任务不得复用同一 ID。结束事件必须带
`outcome=success|cancelled|failed`，取消也配平区间，但不混入成功预览的 p95；不记录只开始不结束的伪样本。

| signpost | category | 起止 / 观测与 §10 指标 |
|---|---|---|
| `CommandFeedback` | `command` | 输入被接收 → 对应可见状态反馈；对应命令反馈，**不表示像素已解码 / 呈现** |
| `FirstPreview` | `render` | 打开 / 导航请求被接收 → 当前目标首个可用预览像素实际呈现；S1 冷应用缓存，RAW / PDF / S3 单独报告 |
| `DecodeQueueWait` | `decode` | 请求入队 → worker 开始，排队取消在取消时收尾；与实际 Decode 分开 |
| `Decode` | `decode` | ImageIO 实际开始 → 阻塞调用返回；记录实际 rowBytes × height、像素宽高、格式与结果，不拿压缩文件大小当解码字节 |
| `WarmMemoryPresent` | `render` | 有匹配像素尺寸的内存命中时，导航输入 → 对应像素实际呈现；与热文件页缓存区分 |
| `DirectoryFirstBatch` | `filesystem` | 扫描请求接收 → 第一批可浏览项可用；不是扫描完成 |
| `DirectoryScan` | `filesystem` | 扫描请求接收 → 最终扫描结果应用；完整耗时另记 |
| `DirectoryReconcile` | `filesystem` | 受控夹具停止写入 → 核对结果应用；无法获知真实停止写入时注明边界未知，不将通知到达当作停止写入 |
| `FramePresent` / `FrameHitch` | `render` | 呈现时间点 / hitch 区间，配合 Instruments 的实际 frame / hitch 数据；记录显示刷新率，不能用请求重绘的时间冒充呈现 |
| `MemoryReservation` | `decode` | 取得内存预约 → 解码真正返回后释放；取消不提前释放，检查预约与执行期重叠 |
| `ResourceSnapshot` | `performance` | 记录实际 worker / queue / cache 数量与字节、RSS、retained objects；三轮浏览及回到空闲时各记快照；读不到的字段记未知 |
| `DiskCacheConverge` | `cache` | 写入 / 淘汰压力开始 → 收敛到配置高水位以内；磁盘缓存实现后才测 |
| `AccessLease` | `access` | 首次 startAccess → 最后一次 stopAccess；用于检测关闭后的访问范围泄漏，不把窗口关闭当作已释放 |

每类时延至少 30 次，保存样本数、p50 / p95 / 极值与成功 / 取消 / 失败数量。每份结果记录机型、芯片、
内存、macOS、Release 构建 SHA、显示器 / scale / 刷新率、存储介质、manifest SHA、缓存状态、重复次数。
冷应用缓存仅指 picsee 内存 / 磁盘缓存；OS 文件页缓存独立注明。未测不填数，样本不足不写“通过 p95”。
不在 MacBook 的正确性检查中冒称 Mac mini 基准达标。
