## 本次工程检查

```sh
xcodegen generate
swift test --package-path Packages/PicseeKit
xcodebuild build -scheme Picsee -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO -derivedDataPath .build/dd-ci
xcodebuild build -scheme Picsee -destination 'platform=macOS' -derivedDataPath .build/dd-signed
```

已观察到工程生成成功、Swift Testing 的 `itemIDSurvivesJSONRoundTrip()` 通过（1 test），两条构建命令均输出 `** BUILD SUCCEEDED **`。
RED 是先提交测试、尚无 ItemID 时的编译失败；RED/GREEN 输出见 PR 描述，不是 tdd-guardian receipt。

`project.yml` 固定手动签名、团队 GRT84NAK4T；App Sandbox 和用户选择文件只读权限在 tracked entitlements 中声明。
构建后脚本在签名前将当前短 SHA 写入 `PicseeGitSHA`；tracked 文件相对 HEAD 有修改时附加 `-dirty`，忽略未跟踪文件（包括 delegator 复制的 `.codex/rules/`）。每次构建均更新该值。
`ENABLE_USER_SCRIPT_SANDBOXING=NO` 仅在 PicseeApp target 配置，针对其构建脚本：它需要读取 linked worktree 外的共享 Git 元数据，并更新产物 Info.plist；App Sandbox 始终开启。

CI 工作流 `CI` 的必需 job check 为 `Walking skeleton`，依次执行 `Checkout`、`Select locked Xcode`、`Install XcodeGen`、`Generate project`、`Swift Testing`、`Build unsigned app`；缺少指定 Xcode 路径或 build 17F113 就失败。CI 从官方 release 下载 XcodeGen 2.44.1，校验工作流中固定的 SHA-256 并断言版本；不使用签名证书。首次 hosted CI 与分支保护由 delegator 推送后执行，本次未声称通过。
