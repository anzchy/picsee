# 性能数字核验清单（P3-08）

每个写入 `docs/validation/` 的性能数字，以及每次引用性能数字来修改功能账簿的「限制：」或状态，都必须先在对应验证记录中填写本清单，并给出运行 ID 与证据位置。未填完的数字不得进入验证记录或账簿。账簿只链接验证记录，不抄数字。

记录条件沿用[开发计划 §10](../PICSEE_DEVELOPMENT_PLAN.md#10-测试素材与性能目标)：机型/芯片/内存、macOS、显示器/scale、存储介质、素材 manifest、缓存状态、构建 SHA。区分冷应用缓存、热磁盘缓存、热内存缓存；冷应用缓存不等于 OS 文件页缓存也已清空。比较双方使用同一机器和素材档 S1–S6，各自均为按交付配置调优的签名 Release 构建；记录签名、配置、SHA 和调优设置。只有单侧的绝对测量时，也须证明该侧满足这些条件。

## 每个指标回答七个问题

每个回答都引用运行 ID 下的具体证据文件、signpost 区间或计数；无法证明的项目写“未知”，不得猜测。

| 问题 | 运行证据如何回答 |
|---|---|
| 1. 数字受什么限制（CPU、解码、IO、主线程布局等），为什么不是两倍？ | 标出瓶颈阶段的 signpost 耗时、CPU/线程占用、IO 字节与吞吐、队列等待和工作量计数；用阶段占比或容量上界说明两倍改善为何不成立。无法命名限制因素时，结论为 `inconclusive`。 |
| 2. 比较双方是否都按交付方式调优？ | 列出双方签名 Release 构建的 SHA、签名验证、配置与调优设置，以及相同机器、素材 manifest/档位、存储和缓存状态的记录。任一侧未经调优或不是签名 Release 构建，结论为 `inconclusive`。 |
| 3. 是否突破物理上限？ | 用本机核心数、存储介质实测/标称吞吐等与实际处理字节数、任务数、耗时作量纲一致的估算；说明估算依据和余量。超出上限时先查计时边界、缓存命中和计数。 |
| 4. 运行中是否出错、被准入拒绝或返回错误输出？ | 对照 App 日志、错误/拒绝/取消计数与结果正确性核对；逐次记异常及其处理，不能把失败样本静默排除。 |
| 5. 结果能否复现？ | 比较时交替运行 A/B（写出顺序），记录每次原始值、运行次数、中位数与范围。计划 §10.2 的时延指标每类至少 30 次采样，另记 p50/p95 与极值；不足时不得宣称通过 p95。 |
| 6. 对用户等待的端到端路径有影响吗？ | 给出输入到可见结果的 signpost 边界及端到端数值；把阶段改善与完整路径对照，说明用户实际等待是否改变。 |
| 7. 工作是否真的发生在计时区间内？ | 给出计时区间起止 signpost、区间内解码/读取/布局/呈现等操作计数，以及区间外对应计数；仅有 wall clock 不足以证明。 |

## 每个已报告指标的填写模板

在验证记录中为每个指标复制此行，并填入运行 ID 和证据路径。`median / range` 写双方各自的中位数和最小–最大值；时延指标同时附 p50/p95/极值。绝对测量在另一侧填“不适用”，并说明所用目标或基线。

| metric | build (signed Release config) | machine | fixture tier | runs | median / range | limiter | inside-timed-region evidence (signposts and counts) | verdict |
|---|---|---|---|---|---|---|---|---|
| 待填（单位、计时边界、运行 ID） | A/B SHA、签名、Release 配置、调优设置 | 机型/芯片/内存、macOS、显示器/scale、存储介质 | S1–S6、manifest、缓存状态 | A/B 次数与交替顺序、原始值路径 | A/B 中位数、最小–最大值；时延另附 p50/p95/极值 | 限制因素、为何不是两倍、物理上界证据 | 起止 signpost、区间内/外工作计数、日志与正确性证据路径 | 待判定 |

结论只用 `faster`、`slower`、`no measurable difference`、`inconclusive`。比较差异必须由重复运行的范围与端到端结果支撑；证据不足时用 `inconclusive`，不得把它写成 `no measurable difference`。**无法命名限制因素，或比较中任一侧未经交付方式调优，必须判为 `inconclusive`。** 对异常、物理上界冲突或计时区间工作量无法核实的运行，也先判 `inconclusive`，补齐证据后再改结论。
