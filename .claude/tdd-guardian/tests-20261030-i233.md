## Unit: CanvasWindowController File Grant loss/reconnect/watch lifecycle

**Law**: After detected loss, no result admitted before loss may restore pixels, identity, Inspector/AX content or a reconnect prompt for a superseded operation. A successful new open alone admits new content. S5 cases below exercise temporal transitions; they do not claim generated input coverage or introduce SwiftCheck/dependency changes.

### Case: issue233ReconcileLossClearsBeforeSheet
- **Category**: failure
- **Lane**: integration (`app-red`)
- **Spec level**: S3 — real removal or bookmark/scope failure is classified as loss.
- **Input**: Real temporary PNG, settled viewer, visible Inspector; remove the file during a held real header request and release it. Observe the sheet-attachment event.
- **Expected output**: At attachment, loader presentation/file URL are nil, canvas has no image or image-derived AX value, window title is neutral, representedURL/proxy is nil, Inspector has no selected metadata/thumbnail or filename.
- **Observable side effect**: Exactly one reconnect sheet; file remains removed.
- **Assertion strategy**: Level 3/4 — inspect native window, canvas AX and Inspector/model state at sheet attachment, plus empty loader presentation. Supplemental request history cannot replace these assertions.
- **Mock boundary**: None — real FileAccess/bookmarks/filesystem/ImageIO. A gate delegates real I/O and controls timing without fabricating an error.
- **Refactor that would break this**: Clearing only after the user dismisses the sheet, or leaving any secondary presentation intact.

### Case: issue233DecodeFirstLossClearsAndRejectsLateWork
- **Category**: state
- **Lane**: integration (`app-red`)
- **Spec level**: S5 — no-repaint invariant across settled → loss → late completion → cancel.
- **Input**: Settled PNG and populated Inspector; hold reconcile, trigger loader refinement after real removal or loss of file scope, and detect failure first through the loader. Hold any pre-loss decode result where applicable. Cancel the reconnect sheet, then release held results and reconcile.
- **Expected output**: The same full cleared state as the preceding case is present before the sheet and stays cleared after cancellation and every released pre-loss completion. Repeated hints do not create another alert or restart display.
- **Observable side effect**: Cancel dismisses recovery UI without displaying old content.
- **Assertion strategy**: Level 3/4 — assert native values and loader state at detection and after release, using a completion gate to prove late work actually finished.
- **Mock boundary**: None — real file access/ImageIO with timing gates. Inspector reader cancellation/generation behavior is additionally covered by the package case below.
- **Refactor that would break this**: Clearing the canvas but retaining loader/input/access authority, allowing late decode/reconcile to reopen the file.

### Case: issue233WakeAndVnodeDetectLossAndRetireObservers
- **Category**: state
- **Lane**: integration (`app-red`)
- **Spec level**: S5 — subscription lifetime and detection survive repeated notification transitions.
- **Input**: Open a real File Grant, remove or deny the file, separately drive the native vnode event and post `NSWorkspace.didWakeNotification`. Repeat wake after loss, and after replacement open/window close.
- **Expected output**: Both live detection paths reach the same cleared reconnect state. Wake after a superseding open or close cannot clear the replacement or attach a stale sheet. No polling is needed.
- **Observable side effect**: Sheet only for the current loss episode; replacement remains visible.
- **Assertion strategy**: Level 3/4 — resulting native presentation and sheet count/state, rather than observer-registration call assertions.
- **Mock boundary**: None — real filesystem vnode and real notification center; manually posted wake exercises the subscription without sleeping the Mac.
- **Refactor that would break this**: Omitting wake forwarding, retaining a dead-window observer, or capturing the old grant without current-operation checks.

### Case: issue233ReconnectSelectionAndCancelStayFileScoped
- **Category**: state
- **Lane**: integration (`app-red`)
- **Spec level**: S5 — loss/cancel/recovery transitions preserve the file boundary.
- **Input**: First open `original/image.png` and await successful settled presentation; only then run the unchanged Inspector route assertion, await populated Inspector, and induce loss. Drive the real alert to Cancel, and separately to its real file panel. Assert files-only, single-selection configuration and original-parent directoryURL. Close the panel only with `window.endSheet(panel, returnCode: .cancel)` and assert cleared state. After restoring the file, call internal `completeFileReconnection` with its URL; in a fresh loss episode call it with a different PNG having a different aspect ratio. Use the same operation token/context captured by production panel completion. Record native security-scope acquisitions; pair with the package FileAccessPort lease-kind case below rather than decorating the controller's concrete FileAccess. Never call `panel.ok` or synthesize accepted powerbox selection.
- **Expected output**: Cancels preserve empty presentation. The panel selects files only and starts at the original parent. Same-file selection settles on that file; different selection settles on the chosen image identity and dimensions. No root lease or parent enumeration/read request occurs during File Grant detection/reconnection/open.
- **Observable side effect**: New selected pixels/title appear only following successful selection/read; no persisted Access Root is created.
- **Assertion strategy**: Level 3/4 — assert actual presented URL/revision/dimensions after the continuation, empty state after native alert/panel cancel and unchanged root store, with native panel configuration and lease-kind history as supplemental boundary evidence required by AC-2. Compare each recorded native scope URL against the allowed file URLs only after applying `resolvingSymlinksInPath` and `standardizedFileURL` to both sides; reject parent/root URLs even when aliased. Direct continuation acceptance is not evidence that actual powerbox acceptance was verified.
- **Mock boundary**: Native security-scope recorder delegates to the real scope adapter. Controller uses its real concrete FileAccess, filesystem/ImageIO and ordinary openInput. Lease-kind recording belongs to the existing package FileAccessPort seam, covered below.
- **Refactor that would break this**: Enumerating the parent, converting selection into an Access Root, ignoring the selected URL, or restoring pixels on cancel.

### Case: issue233ForegroundForwardingDetectsMissedFileGrantLoss
- **Category**: failure
- **Lane**: integration (`app-red`)
- **Spec level**: S3 — foreground must detect loss even when no vnode hint delivered it.
- **Input**: Use a real AppDelegate, open a real PNG through its open-URL entry, and obtain the created controller through its window's windowController. After settling, deny scope or otherwise arrange a missed vnode notification so presentation remains unchanged. Invoke `applicationDidBecomeActive` on that delegate. Do not call reconcile directly in this case.
- **Expected output**: The foreground callback reaches File Grant reconciliation and produces the fully cleared reconnect state before the sheet; without that forwarding call, the same setup remains showing the settled image until an explicit detection trigger.
- **Observable side effect**: Current window clears and receives one reconnect sheet.
- **Assertion strategy**: Level 3/4 — assert presentation before the callback, then native cleared values and sheet afterward. Controlled revert of the AppDelegate forwarding line must make the new case fail, establishing trigger causality without committing an AppDelegate change.
- **Mock boundary**: Scope denial at the existing native scope boundary, paired with the real-file vnode/removal cases above and `issue73SystemScopeReadabilityReflectsRealFiles`. No AppDelegate test seam or production change.
- **Refactor that would break this**: Dropping foreground forwarding while retaining a correct standalone reconcile implementation.

### Case: issue233PackageFileGrantReadersNeverRequestRootLease
- **Category**: guard
- **Lane**: unit (configured package lane), paired with native integration recovery case above
- **Spec level**: S5 — the file-only authority invariant holds across resolve, watch open, image read and failed retry.
- **Input**: Exercise FileGrantWatchDescriptor and AccessImageSource using their existing FileAccessPort seam and a recorder that supplies real-file leases; test readable and failing File Grant attempts. Record each AccessRequest, without introducing a controller decorator.
- **Expected output**: Successful reads return the real PNG identity/pixels and descriptor, failures propagate, and every lease request is `.fileGrant`; no `.root` request or parent enumeration/read is made.
- **Observable side effect**: File descriptor is closed and leases released after use; no directory is enumerated.
- **Assertion strategy**: Level 1/4/5 — assert actual read result/failure and released descriptor/lease state; request-kind assertions supplement those behavioral outputs.
- **Mock boundary**: Existing FileAccessPort lease recorder only. Paired real-path integration cases are ReconnectSelectionAndCancelStayFileScoped and WakeAndVnodeDetectLossAndRetireObservers, which use concrete FileAccess with real temporary files.
- **Refactor that would break this**: Upgrading a file request to root access, reading the parent to find a renamed file, or forgetting to release the lease/descriptor.

### Case: issue233SupersededReconcileFailureNeverAlerts
- **Category**: guard
- **Lane**: integration (`app-red`)
- **Spec level**: S5 — superseded authority remains rejected after its delayed failure.
- **Input**: Hold reconciliation for A, open and settle B, delete A and release the old read. Separately capture A's recovery operation/context when its real panel is presented and keep that panel/context live. Programmatically open and settle B through newer input while A's panel remains attached. Before cancelling A, invoke accepted `completeFileReconnection` directly with A's restored URL and stale context; then close A's panel only with `window.endSheet(panel, returnCode: .cancel)` for cleanup and deliver accepted A continuation again. Also test the nil/cancel continuation after supersession. Supersession must precede cancellation so cancellation cannot mask a missing operation guard. Never drive accepted powerbox selection.
- **Expected output**: B's presented URL, revision, title, Inspector and AX values remain unchanged after stale accepted completion both before and after panel cancellation. After cleanup no sheet remains or is newly attached.
- **Observable side effect**: Old failure produces no native recovery UI.
- **Assertion strategy**: Level 3/4 — compare B identity and native state before/after old work completion; assert no sheet.
- **Mock boundary**: None — timing gate over real file read.
- **Refactor that would break this**: Removing generation guards or allowing a stale panel callback to call ordinary open after navigation.

### Case: ExistingRenameAndTrashRegressions
- **Category**: boundary
- **Lane**: integration (`app-red`)
- **Spec level**: S2/S3 — distinguish same-volume rename, ordinary `.Trash`, system Trash, missing file and failed re-resolution.
- **Input**: Reuse `issue273TrashDuringReconcileReadClearsWithoutReconnectSheet`, `issue273DotTrashMoveDuringReconcileReadFollowsWithoutSheet`, `issue273TrashDuringLoaderDetailRequestClearsWithoutReconnectSheet`, removal/failed-reresolution cases, `issue140NativeOrdinaryDotTrashMoveKeepsViewerLive`, and read #257's `issue257RenameDuringHeldReconcileReadFollowsWithoutSheet` from its branch before adding equivalent evidence if absent locally.
- **Expected output**: Rename and ordinary `.Trash` follow actual moved identity without a sheet; system Trash clears without a sheet; true loss reconnects. A still-readable original path is not misclassified as loss merely because another read failed.
- **Observable side effect**: Real move/trash/read outcomes, with temporary fixtures cleaned by existing test teardown.
- **Assertion strategy**: Level 3/4 — resulting file URL/revision, representedURL and sheet presence/absence, retaining existing assertions.
- **Mock boundary**: None for filesystem/ImageIO; the existing failed-bookmark adapter case is paired with the real bookmark rename/Trash cases named here and `issue140RealFileGrantTrashIsDeletion`.
- **Refactor that would break this**: Clearing on every vnode hint, omitting bookmark re-resolution or classifying every `.Trash` pathname as system Trash.

## Unit: Existing Inspector and loader generation boundaries

**Law**: Clearing selection or closing an image invalidates earlier presentation work; completing earlier work cannot change the cleared/new selection. The following S5 cases cover that invariant and App cases above prove the loss path invokes the boundary.

### Case: ExistingInspectorAndLoaderLateResultRejection
- **Category**: state
- **Lane**: unit (configured package lane), paired with native integration cases above
- **Spec level**: S5 — generation rejection across clear and later completion.
- **Input**: Reuse `issue136InspectorRejectsLateOldItemAndClearsValuesImmediately`, relevant `ViewerImageGenerationTests`/`ViewerImageCancelTests`, and Inspector thumbnail ownership tests; hold metadata/thumbnail completion, clear the selection, release the old result.
- **Expected output**: Inspector metadata/thumbnail and image presentation remain empty or belong exclusively to the newer selection. No old values reappear.
- **Observable side effect**: Old work completes without changing current presentation; transient ownership is released.
- **Assertion strategy**: Level 4/5 — actual model values/presentation and ownership state, not cancellation call count alone.
- **Mock boundary**: Async metadata/decode test fixtures control their I/O boundary. Real ImageIO/Inspector integration is exercised by the App loss cases and `InspectorMetadataReaderTests`; retain these named real-path pairings.
- **Refactor that would break this**: Dropping generation comparison after await or letting a stale result regain a thumbnail pin.
