Revision 1: closes the spec adversary's canonicalization-timing and production-routing gaps. Supersedes `tests-20261024-050000.md`; all other cases retained.

## Execution and boundary rules

All package cases run in the existing `unit` lane, with selected `swift-red` filters for behavioral WIs. Real temporary directories and `BookmarkStore`/`RecentFolderStore` are used. `$T` means a fresh temporary directory per test; IDs R1/R2 mean independently created values asserted against the actual returned IDs. No real sandbox in package tests, no sleeps. The three existing integration cases below are run as the named `integration` lane; they also appear in the aggregate package suite.

`BookmarkCoding` and `SecurityScope` are macOS boundaries explicitly permitted as doubles by the brief. The shared **adapter pair** is `accessSystemAdapterCreatesAndResolvesRealBookmark` plus `issue73SystemScopeReadabilityReflectsRealFiles`; #73 end-to-end package regression is `issue73ReadableDropSessionOpensEmptyThenReplacesAndRejectsZIP`. These pairings verify real adapters, not actual powerbox authorization. Signed device smoke is still required for sandbox evidence; no package result transfers to that obligation.

Use Swift Testing parameterized scenarios and S5 state-transition invariants. SwiftCheck is the catalog recommendation, but adding it would cross the fenced `Package.swift`; do not add a dependency or claim randomized S4 coverage. Finite release permutations are exhaustive for their stated finite domain, not a property-testing generator.

Exact public signatures/types can be chosen by the implementer within the brief. Here `reconnect`, `rootURL`, and `.alreadyGranted(R2)` name their observable contracts. `AccessRecovery` outputs are `.browse(URL)`, `.reconnect(rootID,lastKnownFolder,displayName)`, and, if the API exposes failures, `.error`. The named production Application entry point `AccessRecovery.openRecent(_:currentURL:host:)` (or one documented equivalent name chosen before RED) must compute and route the decision through the brief's production recovery host contract. Native forwarding calls this same entry point. Q2/Q3 must not use a test-only enum switch or route closure that bypasses this production path.

## WI-1 — Unit: FileAccess reconnect

**Law**: Reconnect preserves root identity and creation metadata; any failed transition preserves the entire prior persistent and published state. Every successful probe start has one stop and every failed start has none.

### Case R1: Failed root reconnects and survives relaunch
- **Category**: state
- **Lane**: unit
- **Spec level**: S5 — failed → connected → relaunched preserves identity.
- **Input**: Grant `$T/old`, save its record; construct another FileAccess with bookmark resolution failing for that record; reconnect its ID to `$T/new`, containing `a.png`.
- **Expected output**: Reconnect returns `$T/new`; subsequent acquire returns a lease with that URL and original ID; rootCovering(`new/a.png`) returns that ID; old-path acquire throws `.outsideRoot`; a fresh FileAccess acquires `new/a.png` under the same ID.
- **Observable side effect**: Exactly one persisted record; new bookmark/display name `new`; original `creatingBuildSHA` and `createdAt` unchanged. All issued leases released.
- **Assertion strategy**: Level 1/2/4 — assert exact returned URLs/IDs, read stored fields, and verify balanced successful starts/stops.
- **Mock boundary**: BookmarkCoding and SecurityScope, enabling deterministic failed resolution.
- **Paired integration test**: Adapter pair above; signed smoke for actual powerbox.
- **Refactor that would break this**: Minting an ID or publishing memory before save; internal renaming would not.

### Case R2: Missing record is recreated under the supplied ID
- **Category**: boundary
- **Lane**: unit
- **Spec level**: S5 — absent → persisted → relaunched identity invariant.
- **Input**: Empty store, independently chosen R1, existing `$T/replacement/a.png`.
- **Expected output**: Reconnect(R1) returns replacement URL; record ID, rootCovering and lease rootID equal R1, including after fresh construction.
- **Observable side effect**: Store contains exactly one record for R1 with current build SHA and chosen folder display name.
- **Assertion strategy**: Level 1/2 — read persisted record and assert outputs; cannot pass through a hardcoded ID.
- **Mock boundary**: BookmarkCoding and SecurityScope.
- **Paired integration test**: Adapter pair; native recovery store remains device-unverified.
- **Refactor that would break this**: Treating missing R1 as a normal grant with a new UUID.

### Case R3: Reconnect failures are atomic for both live and failed roots
- **Category**: failure
- **Lane**: unit
- **Spec level**: S3/S5 — failure preserves state across a parameterized transition table.
- **Input**: Prior state `resolved` or `needsReconnection`; inject each of failed scope start, chosen regular file instead of directory, bookmark-create throwing a declared test error, and real store-directory permission denial during atomic save. Choose a different replacement URL.
- **Expected output**: `.startFailed`, `.invalidFolder`, the declared bookmark error (or its documented typed mapping), and a typed persistence error respectively. After restoring the injected boundary, the prior resolved root still acquires its old URL; the prior failed root still throws `.needsReconnection(R1)`.
- **Observable side effect**: Original store bytes and `records()` exactly equal the pre-call snapshots; no replacement root. Success-count minus stop-count returns to the pre-call value; a denied start adds no stop. Restore permissions in cleanup.
- **Assertion strategy**: Level 1/2/4 — exact errors where specified, byte equality, record equality and observable acquire state, per-URL counts.
- **Mock boundary**: BookmarkCoding/SecurityScope failures only; save failure uses the real filesystem, not a mocked store.
- **Paired integration test**: Adapter pair; real save/rollback bytes are exercised directly here with a tmpdir.
- **Refactor that would break this**: Changing saved/roots before persistence, swallowing a failure, or stopping an unstarted scope.

### Case R4: Authorization precedes validation, bookmark creation and save
- **Category**: guard
- **Lane**: unit
- **Spec level**: S5 — phase ordering protects the unchanged initial state until scope acquisition.
- **Input**: Probe scope's start callback snapshots existing store bytes and bookmark-create count, then creates the chosen directory which did not exist before start. A codec witness records whether a successful scope is live at every create. Also run a denied-start variant with an existing chosen directory.
- **Expected output**: Successful reconnect accepts the directory created by start; start observes original bytes and zero new creations; create observes a live scope. Denied start throws `.startFailed` without creating a bookmark or changing the store.
- **Observable side effect**: Only the successful variant persists the replacement, and its probe is stopped once.
- **Assertion strategy**: Level 1/2/4 — assert successful output plus store snapshots, phase witness and balance. Phase-call observations supplement persisted behavior.
- **Mock boundary**: SecurityScope and BookmarkCoding model authorization timing.
- **Paired integration test**: Adapter pair; actual sandbox enforcement requires signed smoke.
- **Refactor that would break this**: Inspecting the directory, creating its bookmark, or writing a record before scope acquisition.

### Case R5: Another root's canonical folder is rejected without changing either root
- **Category**: guard
- **Lane**: unit
- **Spec level**: S3/S5 — collision rejects the transition while conserving both records.
- **Input**: R1 holds `$T/first`, R2 holds `$T/second`; reconnect R1 to `second`, its trailing-slash URL, and a symlink alias. Also reconnect R1 to a distinct `second-child`/nested selection to prove exact equality rather than containment.
- **Expected output**: Canonical aliases throw `.alreadyGranted(R2)`; R1/R2 still acquire their original URLs. Distinct/nested chosen folder is accepted under R1.
- **Observable side effect**: Collision leaves bytes and records identical, with balanced probe counts; successful distinct reconnect retains two records.
- **Assertion strategy**: Level 1/2/4 — exact collision ID, bytes/record equality and usable old roots; exact-match boundary outcomes.
- **Mock boundary**: BookmarkCoding/SecurityScope; symlink canonicalization uses real filesystem.
- **Paired integration test**: Adapter pair.
- **Refactor that would break this**: Matching path prefixes/containment, allowing a second owner for an exact path, or replacing R2.

### Case R6: Reconnect collision identity is evaluated after selected scope starts
- **Category**: guard
- **Lane**: unit
- **Spec level**: S3/S5 — authorization-time identity, atomic collision and retained root identity.
- **Input**: R1 holds X, R2 holds A, B is distinct/unheld. Selected symlink initially targets A; its successful SecurityScope.start changes it to B. In the reverse scenario it initially targets B and start changes it to A. Use real temporary symlinks and reset between scenarios.
- **Expected output**: A→B accepts reconnect under R1 and persists a bookmark resolving to B; R2 still owns A. B→A throws `.alreadyGranted(R2)`; R1 remains X and both original records/store bytes remain unchanged.
- **Observable side effect**: Only accepted post-start B replaces R1; created bookmark, returned URL/lease canonical destination and persisted record all agree on B. Every successful probe start is stopped once; collision creates no replacement bookmark.
- **Assertion strategy**: Level 1/2/4 — exact ID/collision outcome, independently resolved saved bookmark, old-record/byte preservation and per-URL scope balance.
- **Mock boundary**: SecurityScope changes only the selected test symlink at start; BookmarkCoding round-trips the real post-start canonical destination.
- **Paired integration test**: Adapter pair; native powerbox remains separate. Existing LinkChangingScope regression supplies the established boundary-timing pattern.
- **Refactor that would break this**: Caching selected canonical identity before start, then rejecting the wrong owner or persisting a bookmark for a different identity.

## WI-3 — Unit: acquire/release across root URL generations

**Law**: Each token belongs to the URL session that created it. For every URL, successful starts equal stops once all tokens are released; an active token prevents its own session from stopping. Duplicate release is idempotent.

### Case L1: Reconnect preserves old-token ownership
- **Category**: state
- **Lane**: unit
- **Spec level**: S5 — conservation across an explicit rebind.
- **Input**: Grant old, acquire A(old), reconnect same ID to new, acquire B(new), attempt old-path acquire, release A, then B. Probe and grant events are separately identifiable in the double.
- **Expected output**: A.url=old, B.url=new, B.rootID=A.rootID; new old-path acquire throws `.outsideRoot`. Releasing A adds exactly one stop(old) without stop(new); releasing B adds exactly one stop(new).
- **Observable side effect**: At reconnect completion the old lease remains active; after all releases each URL has equal successful starts/stops. Stop suffix for held sessions is `[old,new]`.
- **Assertion strategy**: Level 1/2/4 — lease outputs and exact intermediate per-URL counts/ordered stop suffix; not merely total count.
- **Mock boundary**: BookmarkCoding and per-URL SecurityScope double.
- **Paired integration test**: Adapter pair and #73 regression; actual security-scope semantics covered by native signed smoke.
- **Refactor that would break this**: Releasing by the root's current URL instead of token ownership, or sharing one session key across URLs.

### Case L2: Stale relocation while a lease is live starts a new session
- **Category**: state
- **Lane**: unit
- **Spec level**: S5 — the same conservation invariant across implicit stale repair.
- **Input**: Acquire A at old; set FakeBookmarks.relocated=new and stale=true while A remains held; acquire B(new), then reject old-path acquire; release B before A.
- **Expected output**: B uses new and saved bookmark changes to new; A retains old; old-path acquire throws `.outsideRoot`. Stop suffix is `[new,old]`.
- **Observable side effect**: Exactly one live held session per URL; fresh FileAccess acquires new after persistence; each URL balances after releases.
- **Assertion strategy**: Level 1/2/4 — exact lease URLs, saved bookmark, intermediate counts and stop order.
- **Mock boundary**: BookmarkCoding relocation/staleness and per-URL SecurityScope.
- **Paired integration test**: Adapter pair; WI-0 supplies native relocation observations, signed HEAD smoke confirms current behavior.
- **Refactor that would break this**: Skipping bookmark resolution whenever any root token exists, or stopping the old session during publication.

### Case L3: Sharing, finite release permutations and duplicate release conserve scopes
- **Category**: state
- **Lane**: unit
- **Spec level**: S5 — exhaustive finite token-order transition invariant, not randomized S4.
- **Input**: Two tokens A1/A2 at old, reconnect, two tokens B1/B2 at new; parameterize release orders `[A1,A2,B1,B2]`, `[B1,A1,B2,A2]`, `[A2,B2,A1,B1]`, and reverse. Release each token twice.
- **Expected output**: First release within each URL does not stop that session; last unique release stops it once; duplicate releases add no stop. Tokens within a URL share that URL session, new and old do not share one.
- **Observable side effect**: At every transition `stops(url) <= successfulStarts(url)` and a positive live-token count means its held session is not stopped; final starts=stops separately per URL.
- **Assertion strategy**: Level 1/2/4 — explicit expected counts after each release, not a tautological calculation from the implementation.
- **Mock boundary**: BookmarkCoding and per-URL SecurityScope.
- **Paired integration test**: Adapter pair and #73 regression.
- **Refactor that would break this**: Double stopping, stopping on the first token, root-only keying, or release-order dependence.

### Case L4: Failed stale refresh leaves old leases releasable
- **Category**: failure
- **Lane**: unit
- **Spec level**: S3/S5 — failure never corrupts ownership of an already-issued token.
- **Input**: A held at old; relocate+stale to new; fail bookmark creation, or deny new scope start, in separate scenarios; attempt B(new), then release A twice.
- **Expected output**: B throws the documented typed acquisition error; no B lease exists. A's first release stops old exactly once; second release does nothing. A denied start(new) causes no stop(new); a successful new start followed by refresh failure gets one matching stop(new).
- **Observable side effect**: Prior persisted bytes unchanged; old held-session ownership survives; successful starts/stops balance per URL after cleanup.
- **Assertion strategy**: Level 1/2/4 — errors, store-byte equality and exact old/new counts.
- **Mock boundary**: BookmarkCoding and per-URL SecurityScope.
- **Paired integration test**: Adapter pair.
- **Refactor that would break this**: Clearing all root sessions on refresh failure, stopping the new URL for A, or leaking the unsuccessful refresh's probe.

### Case L5: Same-URL stale acquisition still shares one refreshed session
- **Category**: determinism
- **Lane**: unit
- **Spec level**: S5 — unchanged-URL sharing preserves start/stop conservation and refresh idempotence within a session.
- **Input**: Grant a folder, set stale=true, acquire A and B without relocation; codec remains stale on every resolve as existing FakeBookmarks does. Release A then B.
- **Expected output**: Both lease URLs equal the granted URL; total bookmark creations remain two (grant plus one refresh), matching existing regression; releasing A does not stop the shared session, releasing B does.
- **Observable side effect**: Store has one root; successful start/stop counts equal the established sharing behavior, and final counts balance.
- **Assertion strategy**: Level 1/2 — output URLs plus meaningful bookmark-creation count and scope resource conservation.
- **Mock boundary**: BookmarkCoding persistent-stale behavior and SecurityScope.
- **Paired integration test**: Adapter pair; existing `accessAcquireRefreshesNewlyStaleBookmarkAndRejectsLostRoot` remains regression coverage.
- **Refactor that would break this**: Recreating a bookmark or opening a new scope for every same-session acquire.

## WI-4 — Unit: rootURL and AccessRecovery decisions

**Law**: Recovery grants no authority and persists nothing. Browse follows the currently published root URL independently of stale Recent data; reconnect retains the Recent root ID and user context. Repeated queries/decisions are observationally idempotent.

- **Lane**: unit

- **Expected output**: nil for missing/failed; exact original URL for resolved; exact new URL for relocated/reconnected. Repeated calls agree.
- **Observable side effect**: None: bytes/records and bookmark-creation count unchanged by query itself.
- **Assertion strategy**: Level 1/2/4 — exact optional URLs plus unchanged real persistence snapshots.
- **Mock boundary**: BookmarkCoding/SecurityScope for establishing states only.
- **Paired integration test**: Adapter pair; signed smoke validates real current-URL browsing.
- **Refactor that would break this**: Returning an obsolete saved/Recent URL, implicitly granting a missing root, or repairing storage during a read-only query.

### Case Q2: Production recovery entry point routes browse at the current URL
- **Category**: state
- **Lane**: unit
- **Spec level**: S5 — independently varying stale reference context cannot override current authority.
- **Input**: Invoke the named PRODUCTION Application recovery entry point `AccessRecovery.openRecent(_:currentURL:host:)` with Recent(R1,`$T/old`,`old`) and published `$T/new`, then with R1's obsolete path/name changed independently; invoke it for R2 with another current URL. - **Refactor that would break this**: Leaving native recovery on a bypass path, dropping dispatch, routing a stale Recent URL, or ignoring the root ID. Internal renaming does not break it.

### Case Q3: Production recovery entry point routes original reconnect context
