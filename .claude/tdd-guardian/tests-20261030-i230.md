## WI-1 — Unit: AccessMonitor#reportReadFailure and foreground/wake bridge

**Law**: A loss episode increments authority once; old/cancelled evidence cannot revoke newer authority. Reader and lifecycle checks share the same root/counter verification.

### Case: t230RealRootDenialOnForegroundAndWakeInvalidatesHeldPermit
- **Category**: failure
- **Lane**: integration
- **Spec level**: S3 — a retained security scope/lease does not prove continued readability.
- **Input**: Real temporary root with PNG, pre-loss permit and held FileAccess lease; chmod root 000; post separately didBecomeActive and NSWorkspace.didWakeNotification. Restore mode in cleanup before removing root.
- **Expected output**: lost(accessExpired), counter greater than old counter, old permit invalid despite held lease; no false readable notification.
- **Observable side effect**: Root state and presentation authority revoked; balanced lease release after test.
- **Assertion strategy**: Level 3/4 — inspect actual state and permit after awaited loss, and independently demonstrate real listing refusal. Never assert only that a listing method was called.
- **Mock boundary**: Bookmark/security-scope and disk-mount OS ports may use existing fakes so temporary roots need no interactive panel; actual directory read and chmod are real.
- **Paired integration test**: accessSystemAdapterCreatesAndResolvesRealBookmark and issue73SystemScopeReadabilityReflectsRealFiles cover real adapters; this case covers actual POSIX refusal/listing. True sandbox/TCC revocation remains device NOT VERIFIED.
- **Refactor that would break this**: trusting a live lease instead of enumerating, or mapping denial to unknown.

### Case: t230ReaderSourcesVerifyRootRatherThanUnreadableChild
- **Category**: boundary
- **Lane**: integration
- **Spec level**: S2 — root versus child scope distinction.
- **Input**: Real readable root with unreadable image/subfolder; submit existing reader error signals from scan, thumbnail, viewer, Inspector and watcher paths. Repeat after denying the root itself.
- **Expected output**: Child refusal preserves readable state/counter; root refusal produces lost(accessExpired) from each source.
- **Observable side effect**: No root-wide clearing for isolated child failure; root-wide authority invalidation for root failure.
- **Assertion strategy**: Level 3/4 — compare availability/counter/permit and, for App reader composition cases, actual cleared window content.
- **Mock boundary**: Existing external file/watch/metadata error ports only; real AccessState, AccessMonitor and root listing.
- **Paired integration test**: t230RealRootDenialOnForegroundAndWakeInvalidatesHeldPermit; real scan/ImageIO paths in t230WarmCachesNeverDeliverAfterRootDetection; existing watcher composition tests in LostAccessWindowTests.
- **Refactor that would break this**: equating descendant EACCES with root loss or swallowing one reader's access failure.

### Case: t230ConcurrentReaderForegroundWakeShareOneLossEpisode
- **Category**: state
- **Lane**: unit
- **Spec level**: S5 — idempotent loss and stale-authority rejection across interleavings.
- **Input**: Parameterized traces: reader→activation→wake, activation→reader→wake, wake→reader→activation, each while existing mount-enumeration gate holds the root check; duplicate each input, cancel one waiter, optionally replace authority before releasing gate.
- **Expected output**: Unchanged authority after replacement/stale evidence; otherwise exactly one counter increment and one lost episode, all previous permits invalid. A cancelled waiter cannot cancel another's valid evidence.
- **Observable side effect**: One observable root-loss event per episode; unrelated root unchanged.
- **Assertion strategy**: Level 4 — compare counters/events/permits; check enumeration count only as supplemental coalescing evidence after a positive gate handshake.
- **Mock boundary**: Existing disk-mount OS port with deterministic continuation gate.
- **Paired integration test**: t230RealRootDenialOnForegroundAndWakeInvalidatesHeldPermit; t229FixConcurrentAccessFailuresShareOneRootCheck and t229FixWakeRechecksSavedRootsOnce remain regression coverage.
- **Refactor that would break this**: starting independent lifecycle checks, using a newer stamp after await, or making one caller's cancellation cancel shared verification.

## WI-2 — Unit: ThumbnailDiskCache#prepare/load and AccessImageSource#image

**Law**: Revoked work never becomes deliverable after later recovery. Permission evidence cannot transition into a cache miss or fallback image.

### Case: t230FingerprintAndPayloadPermissionCannotBecomeMiss
- **Category**: failure
- **Lane**: integration
- **Spec level**: S3 — source fingerprint and actual cache-payload permission failures must propagate.
- **Input**: Real cache populated from PNG; deny source read for prepare, separately deny actual cached payload read after a ticket exists; compare damaged/missing payload controls. Reuse t229RealSourceFingerprintPermissionIsNotACacheMiss where equivalent.
- **Expected output**: Permission cases throw an AccessReadFailure-recognized refusal; corrupt/missing payload yields the documented miss and may fresh-decode. Never infer root loss from a cache-only denial without verifying root readability.
- **Observable side effect**: Existing payload retained; no source decode/memory fallback on refusal.
- **Assertion strategy**: Level 3/1 — catch exact permission category from real filesystem/cache; compare returned miss/output for control; decode counters only supplement no-image behavior.
- **Mock boundary**: none for actual source/cache filesystem and ImageIO; use existing decoding boundary instrumentation only to observe forbidden fallback if needed.
- **Paired integration test**: t229RealSourceFingerprintPermissionIsNotACacheMiss and this real payload case.
- **Refactor that would break this**: broad catch returning nil on EACCES, including fingerprint or post-read validation paths.

### Case: t230WarmCachesNeverDeliverAfterRootDetection
- **Category**: state
- **Lane**: integration
- **Spec level**: S5 — warm memory/disk content does not outlive authorization generation.
- **Input**: Real ImageIOPipeline, FileAccess and disk cache; warm both caches and show root image in grid/viewer; deny root and detect using monitor; request with old permit, then restore mode and explicitly recover root.
- **Expected output**: No old request/image accepted or displayed after loss, with viewer/title/proxy/Inspector/AX cleared. Cache bytes may remain; fresh authority can use valid cached content after verification, but old authority stays invalid.
- **Observable side effect**: Presented pixels removed; stored cache retained; recovered root readable with fresh permit.
- **Assertion strategy**: Level 3/4 — inspect delivery errors/permit and native presentation values, not cache-call wiring. Reuse t229WarmedMemoryOriginCannotSurviveRecovery and existing AccessCacheBarrierTests where already exact.
- **Mock boundary**: Fake bookmark/scope and mount ports for noninteractive fixture; real cache, pipeline, AccessState and root filesystem.
- **Paired integration test**: accessSystemAdapterCreatesAndResolvesRealBookmark; issue73SystemScopeReadabilityReflectsRealFiles; t230RealRootDenialOnForegroundAndWakeInvalidatesHeldPermit.
- **Refactor that would break this**: consulting memory cache before authority, untagged disk hits, or reviving an old permit during recovery.

### Case: t230InflightDecodeCannotPublishAfterLossAndRecovery
- **Category**: state
- **Lane**: unit
- **Spec level**: S5 — result generation is immutable across loss/recovery.
- **Input**: Existing externally gated decode seam; traces loss→decode completion and loss→recovery→decode completion, for thumbnail and viewer work. Await positive decode-start handshake before loss.
- **Expected output**: Old result cannot enter deliverable cache or displayed state in either trace; new-authority request can complete normally.
- **Observable side effect**: Old presentation remains empty; leases held until actual decode returns then balanced; no stale cache entry deliverable.
- **Assertion strategy**: Level 4 — inspect no presented image, invalid old permit and balanced leases; new request result proves decoder fixture usable.
- **Mock boundary**: Image decode OS boundary only, gated to force order; no replacement for AccessImageSource/AccessState/cache policy.
- **Paired integration test**: t230WarmCachesNeverDeliverAfterRootDetection plus existing real pipeline/cache AccessCacheBarrierTests.
- **Refactor that would break this**: checking authority only before await, releasing lease on cancellation before decode returns, or accepting old image after recovery.
