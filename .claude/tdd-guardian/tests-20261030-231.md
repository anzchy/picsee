## Unit: AccessCauseClassifier and AccessMonitor cause mapping (WI-1)

**Law**: Proven loss never permits delivery of a previously issued work stamp; retries cannot silently confer readability. S5 transition case below covers this law. Cause copy itself has no algebraic law: it is a finite mapping.

### Case: t231MountedMissingTrashAndUnknownCausePartitions
- **Category**: boundary
- **Lane**: unit
- **Spec level**: S2 — finite cause evidence partitions.
- **Input**: Saved UUID A mounted; resolution error Cocoa 259; same facts with nil UUID; unavailable UUID A; resolved root with denied listing; resolved root with EIO listing; `isInTrash=true` both with successful and failed resolution.
- **Expected output**: Respectively notFound, unknown, diskNotConnected, accessExpired, unknown; actual Trash gives notFound regardless of resolution success.
- **Observable side effect**: none.
- **Assertion strategy**: Level 1 — exact classification cause and Trash flag; preserve existing `accessCauseMountedVolumeWithFailedResolutionIsNotFound`, `accessCauseOtherListingFailureIsUnknown`, permission and nil-UUID cases.
- **Mock boundary**: none — real classifier on value evidence.
- **Paired integration test**: not required.
- **Refactor that would break this**: Changing public classification semantics; private renames do not.

### Case: t231ReadForegroundWakeReportNotFoundAndInvalidateOldWork
- **Category**: state
- **Lane**: integration
- **Spec level**: S5 — readable→lost→retry stays non-deliverable until verified.
- **Input**: Register readable root, hold permit/stamp, delete root or fail its bookmark, drive reader report/foreground/wake; retry while still missing, then restore readable identity where valid.
- **Expected output**: All loss inputs give `.lost(.notFound)`; old stamp/permit is invalid; no repeated loss-counter churn from retries; newly verified recovery does not validate old permit.
- **Observable side effect**: Access state changes and content delivery rejection.
- **Assertion strategy**: Level 4 — exact availability/counter transition, `mayDeliver(old)==false`, permitted new work only after proof.
- **Mock boundary**: Mount notifications/bookmark failures at OS ports; use real FileAccess/state and temp directories.
- **Paired integration test**: t231RealBookmarkMissingRenameAndPlainTrash; existing `accessSystemAdapterCreatesAndResolvesRealBookmark` and `t229FixRepeatedActivationChecksEachRootOnce`.
- **Refactor that would break this**: Publishing readable state without proof or retaining old authority.

## Unit: persisted root replacement/merge (WI-2)

- **Expected output**: One replacement for A, C unchanged, new location persisted and survives reopen; Undo returns all record values/order and Recent Items exactly to before. If A ID is retained for replacement, explicitly assert it; destination authority must still be new.
- **Observable side effect**: Real persisted files and actor state change, then restore; no filesystem folder move/delete.
- **Assertion strategy**: Level 2 — reload stores, compare full arrays and captured bytes where exact-byte restoration is required; verify no duplicate IDs/paths.
- **Mock boundary**: Bookmark/scope OS ports only for deterministic scopes; stores are real.
- **Paired integration test**: t231RealBookmarkMissingRenameAndPlainTrash and existing `accessSystemAdapterCreatesAndResolvesRealBookmark`.
- **Refactor that would break this**: Dropping saved metadata or restoring only visible root names.

### Case: t231RebindMergeKeepsExistingIDAndUndoRestoresBothRecords

## Deferred

- Signed sandbox device smoke, actual system panel interaction, pixel parity and VoiceOver observation: delegator/non-implementer responsibility; record NOT VERIFIED.
- No GUI tests, no design asset edits, no #232/#233 expansion.
- Truly crash-atomic two-file recovery after abrupt process kill is not claimed without a durable journal; logical transaction rollback during handled errors is required. Flag separately if implementation intends a stronger guarantee.
