# Test Matrix — WI-1: historical Recent remapping

Plan: `.claude/tdd-guardian/plan-20261030-fix1.md`.
Integration classifications below run through the existing SwiftPM unit runner or App lane; no lane/config edits are required.

## Unit: FileAccess#rebind

**Law**: Rebind removes source authority while preserving found relative references, and successful Undo round-trips persisted bytes exactly.

### Case: Historical follow then loss rebinds every found reference
- **Category**: state
- **Lane**: integration
- **Spec level**: S5 — composed root transitions preserve reference correspondence and Undo round-trip.
- **Input**: Parameterize fresh versus already-granted replacement. Grant A at old, save root/child Recents, open B, rename A twice, probe/follow each location without rewriting old Recents; seed references at an intermediate and latest path; remove A; replacement contains corresponding child.
- **Expected output**: Fresh replacement has new ID; merge retains replacement ID; no corresponding found Recent references A; mapped child URLs/metadata are exact; replacement root occurs once; B unchanged.
- **Observable side effect**: Real roots/Recents persistence reloads reflect mapping; Undo restores pre-rebind bytes including sidecar absence where applicable.
- **Assertion strategy**: Level 2/3 — read persisted records and URLs, count root occurrence, compare source-free IDs and exact Undo byte snapshots.
- **Mock boundary**: None for persistence/filesystem. Existing bookmark/scope ports may use existing fakes to deterministically publish rename evidence.
- **Paired integration test**: Existing `t231RealBookmarkMissingRenameAndPlainTrash` and `accessSystemAdapterCreatesAndResolvesRealBookmark` cover real bookmark adapter; prefer real bookmark for this new sequence if cheap.
- **Refactor that would break this**: Dropping historical locations, using one suffix for all references, removing source without remapping or losing Undo state.

### Case: App foreground follows inactive A then rebind repairs old Recent
- **Category**: state
- **Lane**: integration
- **Spec level**: S5 — foreground-follow/loss/rebind preserves Recent correspondence across window navigation.
- **Input**: RecoveryFixture A child Recent; controller browses B; same-volume move A using fixture helper; foreground recheck follows A; delete moved A; show A notFound and choose replacement with child through existing selection entry point.
- **Expected output**: B remains displayed during foreground follow; final replacement grid and Undo strip appear; old A references disappear and child is mapped; replacement root entry occurs once.
- **Observable side effect**: Real persisted Recent list and controller presentation state.
- **Assertion strategy**: Level 2/4 — inspect actual Recent store after operation completion plus visible grid root/strip; no assertion on private method calls.
- **Mock boundary**: Existing bookmark/scope and panel-selection system ports only, no internal-module mocks.
- **Paired integration test**: Package real-bookmark sequence above plus existing App rebind/Undo tests cover actual orchestration; actual system panel remains disclosed device-smoke gap.
- **Refactor that would break this**: Foreground check updates only active roots, UI bypasses historical remapping or scan adds duplicate replacement Recent.

### Case: Existing destination safety and uncertain existence regressions
- **Category**: guard
- **Lane**: integration
- **Spec level**: S3 — retained named failures must not become deletion or escaping grants.
- **Input**: Existing `t231RecentRemapChecksResolvedSymlinkContainment`, `t231RecentRemapDropsOnlyConfirmedMissing`, `t231RebindKeepsLexicalSourceSuffixBeforeResolvingDestination`, collision and Undo cases.
- **Expected output**: Escaping symlink unresolved reference retained; only ENOENT/ENOTDIR equivalents dropped; EACCES/EPERM/EIO references retained; metadata/collision behavior unchanged.
- **Observable side effect**: Persisted mapped Recent values.
- **Assertion strategy**: Level 1/2/3 — existing expected Recent arrays and exact persistence comparisons, unchanged assertions.
- **Mock boundary**: Existence-error injection at system I/O port only.
- **Paired integration test**: Existing real-filesystem symlink and missing-child cases in AccessRebindTransactionTests.
- **Refactor that would break this**: Canonicalizing source descendants early, broad error dropping or removing destination containment.

# Test Matrix — WI-2: retryable failure reporting

## Unit: FileAccess#transaction diagnostics

**Law**: A successful transaction has one commit and no error; a handled failed transaction has no commit and preserves the pre-operation state when rollback succeeds.

### Case: Transaction output corresponds to persisted outcome
- **Category**: state
- **Lane**: integration
- **Spec level**: S5 — output and persistence agree over success, failed write and rollback transitions.
- **Input**: Existing real temporary stores; successful Rebind/Undo; unsupported schema before mutation; chmod-based second-store write failure with successful restoration; preserve existing error expectations.
- **Expected output**: Bounded attempt/commit/rollback/error events identify root ID, operation/stage/kind; preparation failure has no commit; write failure records rollback and error; thrown typed errors remain unchanged.
- **Observable side effect**: Output events from the logging boundary plus real root/Recent bytes.
- **Assertion strategy**: Level 1/2 — assert thrown error and exact state/persistence relation; event field/count checks supplement those observations.
- **Mock boundary**: Log output collector only; storage and transaction real.
- **Paired integration test**: This same real-store case exercises the production transaction generating events; production os.Logger uses bounded event fields. Unified-log delivery is platform-owned and not asserted.
- **Refactor that would break this**: Reporting commit before writes finish, losing original error type, omitting rollback outcome or logging unbounded raw error/path descriptions.

## Unit: CanvasWindowController#Rebind and Undo failure indication

**Law**: One failed user transaction produces one failure indication and remains retryable; success/cancellation produce none.

### Case: Failed Rebind then failed Undo remain audible and retryable
- **Category**: state
- **Lane**: integration
- **Spec level**: S5 — failure/retry transitions preserve committed state and exactly-once indication per failure.
- **Input**: Extend `t231RebindFailureAndUndoFailureRemainRecoverable` with injected failure-output collector. Unknown Recent schema fails Rebind; restore schema and retry; unknown roots schema fails Undo; restore schema and retry.
- **Expected output**: First failure emits exactly one rebind-stage/safe-kind indication, Lost Access buttons enabled and original root persists. Successful retry adds no failure; second failure adds exactly one undo-stage/safe-kind indication, replacement and Undo strip remain; final retry restores original state and adds no failure.
- **Observable side effect**: Reporter output, persisted roots/Recents, Lost Access/grid/strip/control state. Default production failure output performs `NSSound.beep()`.
- **Assertion strategy**: Level 2/4 — preserve existing state/persistence assertions and add indication counts/stage/kind; count/args alone are insufficient.
- **Mock boundary**: Audible output sink replaced by collector to avoid noise; real App orchestration and schema stores.
- **Paired integration test**: This App-lane case drives real operation failures and production reporter call site. Audible delivery itself is platform-owned; default closure calling NSSound.beep is source-reviewed, not a device-hearing claim.
- **Refactor that would break this**: Silent catch, duplicate indication, consumed Undo on failure or controls not reenabled.

### Case: Cancelled selection preserves Lost Access silently
- **Category**: guard
- **Lane**: integration
- **Spec level**: S5 — cancellation is an identity transition with zero failure indications.
- **Input**: Existing cancellation test with failure-output collector; cancel selection while A is notFound, then complete a successful Rebind/Undo.
- **Expected output**: Cancellation leaves original Lost Access and persistence unchanged, controls enabled; no failure output on cancel or subsequent success.
- **Observable side effect**: Controller state and persistent bytes remain unchanged on cancellation.
- **Assertion strategy**: Level 2/4 — compare state/bytes and output count.
- **Mock boundary**: System panel-result and audible sink only.
- **Paired integration test**: Existing App cancellation/rebind cases exercise actual controller paths; actual system open panel remains device-smoke gap.
- **Refactor that would break this**: Treating nil selection as an error or committing state on cancellation.
