# Test Matrix — WI-1: #231 recorded Recent root location

Plan: `plan-20261030-fix2.md`. Scope: F1, P2-08c, ACCESS-03.
`recordedRoot: URL?` is reference provenance, never authority. When present it is the sole source location for suffix derivation; absent values retain latest-first history fallback. Rebind updates a present value to the destination root and leaves absent values absent.

## Unit: RecentFolder persistence

**Law**: Encoding then decoding preserves the entire reference, including optional provenance; missing provenance remains missing.

### Case: Literal old JSON remains legacy through round-trip
- **Category**: state
- **Lane**: unit
- **Spec level**: S5 — legacy representation survives decode/encode/decode without invented provenance.
- **Input**: Literal JSON containing rootID, url `/base/container/album/child`, displayName and openedAt, with no recordedRoot key. A second literal includes recordedRoot `/base/container/album`.
- **Expected output**: Legacy decoded recordedRoot is nil; new decoded recordedRoot equals its literal URL; encoding and decoding each preserves all fields.
- **Observable side effect**: none.
- **Assertion strategy**: Level 1 — inspect nil/present fields and full value equality after round-trip.
- **Mock boundary**: none — real JSONEncoder/JSONDecoder and model.
- **Refactor that would break this**: Persisting inferred current roots in legacy values or silently losing recordedRoot; internal renames do not matter.

## Unit: FileAccess rebind and AccessRecentRemap

**Law**: A recorded reference retains its relative suffix through root movement, rebind, reload and subsequent rebind; Undo restores exact prior bytes. Legacy values retain round-1 semantics.

### Case: Two-move promotion never selects misleading album child
- **Category**: state
- **Lane**: integration — executed by package unit/RED commands, but uses real filesystem and bookmark adapters.
- **Spec level**: S5 — reference meaning survives two observed moves and a replacement transaction.
- **Input**: Real SystemSecurityScope bookmark for A at `container/album`, `child` Recent with recordedRoot at that location; B active while A moves to `staging`, then former parent `container`. Probe A after each move. Delete A; replacement has `child`. Parameterize misleading replacement `album/child` absent/present and destination fresh/already-granted (four cases).
- **Expected output**: Exactly one corresponding destination child reference at replacement/child; none at replacement/album/child. Present recordedRoot becomes replacement. Source root retired; existing destination ID retained for merge.
- **Observable side effect**: Committed bookmark and Recent stores; read back with a fresh RecentFolderStore instance.
- **Assertion strategy**: Level 3 — inspect real stored URLs, root IDs, provenance and metadata; exact child assertion defeats silent missing removal and existing wrong-folder mapping.
- **Mock boundary**: Security scope lifecycle only (existing ReconnectScope avoids signed app requirement), real bookmark codec and filesystem. Native grant delivery remains device-only.
- **Paired integration test**: `accessSystemAdapterCreatesAndResolvesRealBookmark` for actual adapter and `issue73SystemScopeReadabilityReflectsRealFiles` for actual readability; promotion itself exercises real bookmark movement.
- **Refactor that would break this**: Deriving suffix from newest prefix, dropping provenance, using longest-prefix independent of recording epoch.

### Case: Newer-recorded inverse ambiguity uses newer root
- **Category**: state
- **Lane**: integration
- **Spec level**: S5 — same history, different recording epoch must produce a different correct suffix.
- **Input**: After A moves from `container/album` through `staging` to `container`, create and record current `container/album/child` with recordedRoot `container`; replacement contains `album/child` and also `child`.
- **Expected output**: Map to replacement/album/child, never replacement/child. Preserve displayName/openedAt and set recordedRoot to replacement.
- **Observable side effect**: Real committed Recent store.
- **Assertion strategy**: Level 3 — read actual mapped URL and provenance; use same lexical old Recent spelling as promotion case so path precedence cannot distinguish epochs.
- **Mock boundary**: Same scope lifecycle boundary as promotion; real bookmark codec/filesystem.
- **Paired integration test**: `accessSystemAdapterCreatesAndResolvesRealBookmark`, `issue73SystemScopeReadabilityReflectsRealFiles`.
- **Refactor that would break this**: Always choosing the oldest/longest prefix or caching one suffix per root instead of per reference.

### Case: Legacy overlap retains round-1 latest-first fallback
- **Category**: boundary
- **Lane**: integration
- **Spec level**: S2 — absent optional field is a compatibility boundary.
- **Input**: Literal old-record Recent at `container/album/child` with nil recordedRoot and oldRoots `[container, staging, container/album]`; replacement contains album/child.
- **Expected output**: Legacy maps to replacement/album/child, with recordedRoot still nil. No claim of correcting unrecoverable historical provenance for old values.
- **Observable side effect**: Store contains mapped legacy value without invented provenance.
- **Assertion strategy**: Level 1/2 — decode literal legacy input, assert mapped URL and nil provenance after persisted reload.
- **Mock boundary**: none — real model, filesystem probe, store and remapping.
- **Refactor that would break this**: Backfilling provenance or changing legacy fallback to longest-first.

### Case: Updated provenance survives second rebind and Undo
- **Category**: state
- **Lane**: integration
- **Spec level**: S5 — composition and exact restoration across transitions.
- **Input**: Successful promotion rebind, reload Recent store, lose replacement, rebind to replacement2 with same child. Capture all AccessStoreBytes before each transaction. Include fresh/merge variants from promotion.
- **Expected output**: Second target is replacement2/child with recordedRoot replacement2; Undo second restores exact first committed bytes/provenance, Undo first restores original snapshot if its token remains valid (otherwise use independent fresh fixture for each Undo).
- **Observable side effect**: Primary, schema and recovered sidecars, memory records.
- **Assertion strategy**: Level 2/3 — exact AccessStoreBytes equality plus record identity and decoded reference equality; not just a successful return.
- **Mock boundary**: Same scope lifecycle boundary as promotion; real persistence/bookmarks.
- **Paired integration test**: `accessSystemAdapterCreatesAndResolvesRealBookmark`, `issue73SystemScopeReadabilityReflectsRealFiles`.
- **Refactor that would break this**: Keeping the original recordedRoot after URL remapping, or restoring only decoded values instead of exact bytes.

### Case: Invalid provenance cannot become fallback authority
- **Category**: guard
- **Lane**: integration
- **Spec level**: S3 — corrupt/mismatched provenance must not silently select another historical suffix.
- **Input**: Source reference whose present recordedRoot does not contain its URL, plus valid history which would otherwise match. Include a candidate escaping destination through a symlink using existing containment fixtures.
- **Expected output**: Original unresolved reference retained; no outside destination reference or grant, and no provenance-to-legacy fallback.
- **Observable side effect**: No incorrect remap in committed store.
- **Assertion strategy**: Level 1/2 — compare retained source reference; assert no outside URL and no additional access root.
- **Mock boundary**: none — real directories/symlinks and remapping.
- **Refactor that would break this**: Falling back to history when present provenance is unusable, or trusting recordedRoot as access authority.

## Unit: App Recent recording and recovery orchestration

**Law**: A successfully recorded or followed folder keeps its then-current root provenance, and later inactive-root recovery preserves that recorded meaning; active unrelated browsing stays active until explicit selection.

### Case: Production rememberFolder stores provenance and overlapping recovery maps child
- **Category**: state
- **Lane**: integration — App lane with real controller/store orchestration and harness OS boundaries.
- **Spec level**: S5 — browse/remember, inactive moves, foreground follow, loss and explicit recovery preserve reference meaning.
- **Input**: Existing RecoveryFixture with A rooted at container/album and child; invoke production rememberFolder (or complete its normal successful browse), inspect persisted Recent recordedRoot. Browse B; move A to staging then container and foreground-follow after each. Replacement contains both child and album/child. Open stored A Recent, select replacement and pause enumeration before subsequent scan remembers the replacement root.
- **Expected output**: Stored original Recent has original recordedRoot; foreground follow does not overwrite inactive reference epoch; B remains active through inactive follow; committed transaction contains replacement/child, never misleading album/child, and destination provenance replacement. After resume browsing completes normally.
- **Observable side effect**: Actual Recent JSON and controller recovery/display state.
- **Assertion strategy**: Level 2/3 — read persisted provenance and committed child URL before normal scan overwrites per-root Recent; inspect displayed B and final recovered folder.
- **Mock boundary**: Existing bookmark movement, mount and scope fixture boundaries for deterministic controller orchestration; package promotion above uses real bookmarks. No internal remap/store mocks.
- **Paired integration test**: Two-move promotion case above, `accessSystemAdapterCreatesAndResolvesRealBookmark`, `issue73SystemScopeReadabilityReflectsRealFiles`.
- **Refactor that would break this**: Adding model provenance only in tests, forgetting production rememberFolder/grant/reconnect recording, or updating all old Recent epochs during inactive follow.

### Case: Production grant reconnect and reselect persist current provenance
- **Category**: state
- **Lane**: integration — App services with real Recent persistence and existing recovery harness boundaries.
- **Spec level**: S5 — each successful entry transition records the root location current for that transition, independent of prior history.
- **Input**: Fresh grant at A; same-root reconnect after A moves to A2; reselect matching the original root and reselect choosing another folder C. Run each path through production AccessServices, not manually constructed Recent values.
- **Expected output**: Reloaded Recent for each result carries recordedRoot equal to that result's current root URL (A, A2, matched location or C), never the old location or nil; rootID and stored URL agree with the operation result. Include grant into already-known root if supported by the fixture.
- **Observable side effect**: Actual Recent JSON saved by grant, reconnect and both reselect outcomes, inspected with a fresh store and encoded-key inspection.
- **Assertion strategy**: Level 2/3 — assert persisted URL, rootID and recordedRoot after each operation; differing locations defeat a hardcoded initial-root implementation.
- **Mock boundary**: Existing system scope/bookmark/identity fixture boundaries for deterministic App service composition; no Recent/store/service mocks.
- **Paired integration test**: Two-move promotion above plus `accessSystemAdapterCreatesAndResolvesRealBookmark` and `issue73SystemScopeReadabilityReflectsRealFiles` cover real bookmark/readability adapters.
- **Refactor that would break this**: Recording provenance only in rememberFolder while service entry paths retain legacy-style nil or stale roots.
