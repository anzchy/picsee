## Unit: CanvasWindowController#reportFileGrantReadFailure

**Law**: Superseding a probe revokes its authority monotonically: completing any of its suspended operations afterwards cannot mutate the visible state. The cases below assert S5 transition invariance across deterministic race schedules; they are not a claim of generated/exhaustive concurrency testing. SwiftCheck is not installed and no dependency is added for this focused App regression.

### Case: held lease release delivers an old non-cancellation error
- **Category**: state, failure, concurrency
- **Lane**: integration — native App harness via existing `app-red` lane.
- **Spec level**: S5 — observable state is invariant across replacement then stale completion.
- **Input**: Settled original file A; hold unrelated reconciliation if required; P1 receives a real failed open/read and blocks at a test-only SecurityScope.stop gate while releasing its acquired lease on the concrete FileAccess actor. Restore file readability; synchronously start P2 on A without changing access/input/loader generation; synchronously signal the release gate from MainActor, then await both Tasks. P2 subsequently reads successfully.
- **Expected output**: Both Tasks complete; P1 produces no delivery. P2 alone remains authoritative.
- **Observable side effect**: Image/presented key, loader URL/phase/generation, window title/represented URL and Inspector values remain equal to the pre-replacement snapshot; no sheet-start notification, no attached sheet and no cleared image.
- **Assertion strategy**: Level 4 — assert the snapshot before and after P1 completion, plus zero sheet-start events and nonempty presentation. Assert held-release reached before replacing P1 and assert same generation immediately after P2 starts, so input supersession cannot accidentally explain the pass.
- **Mock boundary**: System SecurityScope.stop scheduling boundary only: a test-only NSCondition/semaphore wrapper delegates real scope operations and blocks cleanup off MainActor; real concrete FileAccess, controller, session, image pipeline and FileHandle read execute. Do not stub controller helpers or internal state; do not add production injection seams. Always signal in cleanup before awaiting actor work.
- **Paired integration test**: This case is itself a native integration test with real temporary-file open/read; existing `accessSystemAdapterCreatesAndResolvesRealBookmark` covers the real bookmark adapter contract and `issue233R2InspectorOnlyPOSIXLossClearsBeforeSheet` covers unmodified real access denial delivery.
- **Refactor that would break this**: Only changing the promised visible loss/supersession behavior or removing the public probe completion contract; a helper rename or token representation change does not affect assertions.

### Case: held successful scoped-read release cannot reconcile after replacement
- **Category**: success, state, concurrency
- **Lane**: integration — native App harness via `app-red`.
- **Spec level**: S5 — stale successful read preserves presentation across probe replacement.
- **Input**: A shown under original grant A. P1 acquires a file lease resolving to distinct readable B and successfully performs its real file read; hold SecurityScope.stop in lease release. Use one-shot system resource-identity/bookmark results to resolve P1 to B and subsequent reads to A. Start P2 for original A synchronously at unchanged access/input/loader generations. Signal release, then await P1/P2. P2's access-only byte read must not update the displayed image itself. A stale reconciliation must be observable either as actual extra scoped/ImageIO header I/O after restoring A (no disk revision mutation needed), or as a forced visible reopen using a distinct revision with watch delivery controlled.
- **Expected output**: P1's moved resolved URL cannot initiate reconciliation or reopen after replacement; P2 subsequently completes normally.
- **Observable side effect**: Image/rendered key, loader URL/phase/generation, window title/represented URL and Inspector equal the pre-replacement snapshot; no cleared image or sheet event; no additional actual reconciliation header-read I/O.
- **Assertion strategy**: Levels 3–4 — require held successful release reached, prove generation unchanged at P2 start, assert snapshot/generation equality, and assert real pipeline header-request count unchanged after the two access-only probes. For the no-disk-write schedule, the extra real I/O is the discriminating oracle: an unguarded reconcile of unchanged A may leave pixels/generation unchanged but still performs a scoped header request. Use the concrete access actor completion barrier and task drain so any such request can execute before final assertions. Controlled-revert RED must actually demonstrate this count assertion fails; merely assuming a barrier drains a newly launched task is insufficient. The visible-reopen alternative remains valid. Existing current rename tests ensure reconciliation itself remains functional.
- **Mock boundary**: System bookmark/scope scheduling only, with actual FileAccess, real temporary-file read and native controller. No production seam or internal helper mock.
- **Paired integration test**: This native test exercises concrete FileAccess/read/release; `accessSystemAdapterCreatesAndResolvesRealBookmark` covers unmodified system bookmark contract and `issue233R2ProbeMissingLeasePathPreservesRenameAndTrashRecovery` covers live move recovery.
- **Refactor that would break this**: Changing superseded success delivery behavior, not helper/token representation.

### Case: held bookmark resolution success cannot deliver after replacement
- **Category**: state, guard, concurrency
- **Lane**: integration — native App harness via `app-red`.
- **Spec level**: S5 — stale resolution completion preserves current presentation across replacement.
- **Input**: A shown; P1's acquisition/read indicates missing/reconnection and enters test-only held BookmarkCoding.resolve on the concrete FileAccess actor. Arrange its eventual resolution result so an unguarded continuation would take a visible loss or reconcile/reopen branch. Synchronously start P2 for current A at the same generations, signal P1's resolution gate from MainActor without awaiting that blocked actor, then await P1 and P2. P2 subsequently reads successfully.
- **Expected output**: No stale reconnection, clearing, reconciliation or reopen.
- **Observable side effect**: Same complete presentation snapshot as before release; no sheet-start event/attached sheet, same generation and same rendered key.
- **Assertion strategy**: Level 4 — snapshot equality and zero sheet events after awaiting P1 Task; prove the resolver gate is held and P2 started at unchanged generation. Snapshotting generation catches a stale reconcile/reopen even if it repaints the same image.
- **Mock boundary**: Bookmark system boundary with explicitly held success; real native controller and real filesystem/pipeline. No internal controller mock.
- **Paired integration test**: `accessSystemAdapterCreatesAndResolvesRealBookmark` plus existing `issue233R2ProbeMissingLeasePathPreservesRenameAndTrashRecovery` exercise real bookmark/move semantics; this case exercises suspension policy with the native controller.
- **Refactor that would break this**: A change in the supersession contract, not a renamed internal helper or identity implementation.
