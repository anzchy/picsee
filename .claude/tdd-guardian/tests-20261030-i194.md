## Unit: WI-1 ImageIOInspectorMetadataReader and shared ImageIOPipeline Inspector thumbnail path

**Law**: Shared-memory conservation: every admitted Inspector decode has staging charged while active; completion/failure/cancellation eventually restores staging to baseline. Pins and staging obey the existing shared policy. S5 transition cases below cover this invariant without introducing a property-test dependency.

### Case: real Inspector thumbnail and metadata remain available
- **Category**: success / boundary
- **Lane**: integration (executed by package unit command)
- **Spec level**: S2 — landscape, portrait/rotated, and source smaller than 240 px.
- **Input**: Existing real landscape-3x2.png, portrait-2x3.png, orientation fixture, and a real small PNG; reader injected with ImageIOPipeline.
- **Expected output**: Correct source metadata/type/byte count and PNG thumbnail; longest thumbnail edge is at most 240 px, reaches 240 when source is larger, and upright orientation is preserved; small image is not spuriously enlarged.
- **Observable side effect**: Shared pipeline completion, no outstanding staging.
- **Assertion strategy**: Level 1 / Level 3 — read thumbnail Data using ImageIO and assert dimensions/orientation plus existing metadata values; assert shared budget reserved bytes return to zero.
- **Mock boundary**: none — real implementation.
- **Refactor that would break this**: Removing thumbnail production, requesting the grid edge instead of Inspector edge, dropping orientation transform, or bypassing supplied pipeline.

### Case: exhausted shared budget blocks Inspector until pins release
- **Category**: boundary / state
- **Lane**: integration (executed by package unit command)
- **Spec level**: S5 — pin → queued request → unpin → decode → settled ledger.
- **Input**: Real pipeline with known finite budget and a filler image pinned through pipeline.pin so no staging room remains; reader asks 240 px with visible priority.
- **Expected output**: Request queues with zero reservation and no result while pin holds budget. After pipeline.unpin, real ImageIO output becomes available; no outstanding reservation/job remains.
- **Observable side effect**: Budget/admission queue state changes and valid thumbnail delivery.
- **Assertion strategy**: Level 3 / Level 4 — wait for admission.waiting == 1, assert running/reserved are zero; unpin, await output, assert thumbnail dimensions and waiting/running/reserved zero. Budget peak respects existing allowed pin/staging bound.
- **Mock boundary**: none — real implementation.
- **Refactor that would break this**: Direct ImageIO decoding, independent pipeline construction, or `.current` priority bypassing pin pressure.

### Case: queued cancellation removes Inspector work without decoding
- **Category**: failure / state
- **Lane**: integration (executed by package unit command)
- **Spec level**: S5 — pin → queued → cancel → unpin, with no later zombie work.
- **Input**: Same real exhausted-budget fixture as previous case; cancel the reader task after queue registration.
- **Expected output**: Task fails cancellation according to reader contract; no thumbnail result; waiting and staging return to zero before filler unpin, and remain zero afterward.
- **Observable side effect**: Removed waiting job and balanced resource ledger.
- **Assertion strategy**: Level 1 / Level 4 — assert failure and terminal queue/ledger state, then unpin and recheck zero outstanding work.
- **Mock boundary**: none — real implementation.
- **Refactor that would break this**: Failing to propagate cancellation to pipeline admission or leaving a zombie queued request.

### Case: active success failure and cancellation release only after work finishes
- **Category**: failure / property
- **Lane**: integration (executed by package unit command)
- **Spec level**: S5 — conserve staging across active decode terminal transitions.
- **Input**: Real pipeline with existing ImageDecoding injection boundary wrapping ImageIODecoder; use a bounded condition gate to hold synchronous external decode, then run success, error, and cancel scenarios on valid files. No production API changes for scheduling.
- **Expected output**: Nonzero reservation while decode gate holds. Cancellation cannot release that reservation prematurely. Opening gate yields the appropriate output/error, then exactly zero reserved/running/waiting work.
- **Observable side effect**: Ledger reservation lives as long as synchronous decode and is retired on each terminal path.
- **Assertion strategy**: Level 1 / Level 3 / Level 4 — assert active budget charge, cancel/error outcome, valid success PNG, and eventual zero resource state. Include a decode failure after admission rather than only corrupt-header rejection.
- **Mock boundary**: ImageIO external synchronous decode is held or throws at the existing decoder boundary; real admission/cache remain intact.
- **Paired integration test**: real Inspector thumbnail and metadata remain available; exhausted shared budget blocks Inspector until pins release (both use actual ImageIODecoder).
- **Refactor that would break this**: Releasing on cancellation before worker return, missing error cleanup, or leaking successful reservations.

### Case: metadata errors remain classified and lease-scoped
- **Category**: guard / failure
- **Lane**: unit / integration (existing package tests)
- **Spec level**: S3 — named permission, missing-file, unreadable-image, and unexpected lease failures.
- **Input**: Existing InspectorMetadataReaderTests fixtures and lease failure adapters, with real injected pipeline for successful authorized reads.
- **Expected output**: Existing noPermission/unreadable distinction; header fields retain values; cancelled work does not produce a successful thumbnail.
- **Observable side effect**: No leftover admission jobs or staging after terminal failure.
- **Assertion strategy**: Level 1 / Level 4 — preserve current error/value assertions and add terminal ledger checks where thumbnail work was admitted.
- **Mock boundary**: Existing security-scope lease error adapters for classification; actual granted-file path is covered by controller case below.
- **Paired integration test**: controller toggles Inspector with pinned grid and rejects late old thumbnail.
- **Refactor that would break this**: Changing metadata error mapping, ignoring cancellation, or accidentally retaining direct thumbnail decode in header worker.

### Case: thumbnail-only failures preserve known header metadata
- **Category**: failure / boundary
- **Lane**: integration (executed by package unit command)
- **Spec level**: S3 — admitted pixel-decode failure and thumbnail resource-limit failure after successful metadata/header read.
- **Input**: Valid landscape PNG and shared pipeline whose existing ImageDecoding boundary throws after admission; separately a real pipeline with budget too small for the requested Inspector output. Also exercise a readable source above the existing 40-megapixel thumbnail cutoff if that compatibility guard is retained.
- **Expected output**: Reader succeeds with correct pixelWidth, pixelHeight, typeIdentifier, byte count and dates, but thumbnailData is nil. Do not convert an optional-thumbnail failure into unreadable metadata. Cancellation still propagates rather than returning successful metadata; permission failures retain noPermission semantics.
- **Observable side effect**: Admitted staging returns to zero on decoder failure; resource-limit rejection leaves no queued/running/reserved work.
- **Assertion strategy**: Level 1 / Level 3 / Level 4 — assert full metadata fields and nil thumbnailData, terminal shared-ledger state, plus distinct cancellation and permission outcomes from adjacent cases.
- **Mock boundary**: External synchronous pixel decode throws at the existing ImageDecoding boundary for the admitted failure; resource-limit path uses actual ImageIODecoder and finite budget.
- **Paired integration test**: real Inspector thumbnail and metadata remain available; exhausted shared budget blocks Inspector until pins release.
- **Refactor that would break this**: Catching a thumbnail resource/decode failure as whole-read unreadable, erasing metadata, swallowing cancellation, or leaking staging after failure.

## Unit: WI-2 WindowInspectorReader and CanvasWindowController Inspector lifecycle

**Law**: Latest selection wins across panel/layout transitions. Every grid presentation pin has a balancing release at teardown; Inspector requests cannot outlive their presentation generation. S5 controller transitions below cover both laws.

### Case: controller toggles Inspector with pinned grid and rejects late old thumbnail
- **Category**: state / property
- **Lane**: integration (App compiled app-red/app-lane command)
- **Spec level**: S5 — grid with pins → Inspector opens/narrows grid → Current Item changes → Inspector closes/widens → reopens → new completion then old completion → close window.
- **Input**: Real temporary granted folder with visually distinct portrait and landscape files; real AccessServices, shared ImageIOPipeline and controller default reader. Existing decoder boundary may hold only the old item's 240 px decode; other edges and new item execute ImageIODecoder normally. Use finite bounded waits and explicit gate cleanup.
- **Expected output**: Grid pins exist before opening panel. Inspector gets 240 px thumbnail request, remains visible with new item's correct name/metadata/thumbnail after old work finishes, and stale cancellation reaches admission. Grid width decreases then increases on toggles. After close and work settlement all grid pins and Inspector reservations/jobs are zero.
- **Observable side effect**: Actual controller presentation, thumbnail output, grid layout and pin/staging accounting.
- **Assertion strategy**: Level 1 / Level 3 / Level 4 — inspect controller Inspector known value and decode Data dimensions/content; assert current name and metadata after late completion. Supplement with observed request edge. Assert grid content width relation and terminal shared-cache pin/reservation balance, rather than relying on mock call counts.
- **Mock boundary**: External ImageIO decode scheduling held at existing ImageDecoding injection; real pipeline/admission/cache/access/controller remain active.
- **Paired integration test**: real Inspector thumbnail and metadata remain available; existing issue140Combo136GridInspectorTracksRevisionsWithoutDuplicateReads exercises real WindowInspectorReader/FileAccess path.
- **Refactor that would break this**: Constructing a private Inspector pipeline, using wrong edge, dropping cancellation/generation guard, retaining old output after layout changes, or leaking grid pins.
