# TDD Plan: Grid Inspector follows watched image changes

## Work Items

### WI-1: Refresh Grid Inspector metadata when the selected file revision changes
- **Description**: With the folder grid and Inspector visible, reconcile external changes to the selected image so the Inspector displays the current file. Preserve metadata reads when the selected file is unchanged. Keep the existing viewer and #136 Inspector routes working.
- **Acceptance criteria**:
  - [ ] After an atomic same-path replacement with different dimensions, the Grid Inspector displays the replacement's dimensions while retaining the selected Current Item.
  - [ ] Reconciliation that leaves the selected entry's revision unchanged does not start another Inspector metadata read.
  - [ ] Renaming the selected file updates the Grid Inspector name.
  - [ ] Deleting the selected file moves the Grid Inspector to the visible successor, or clears it when no image remains.
  - [ ] The App test reproduces the stale metadata on the current branch before implementation and records a valid `issue140-COMBO136-WI-1` RED receipt; the same tests pass after implementation.
  - [ ] INFO-02 and FOLDER-07 ledger limits describe only the supported coverage level; acceptance text stays byte-identical and HTML is regenerated.
- **Required tests**:
  - Real App-level grid-visible Inspector with an authorized temporary folder: atomically replace the selected image with different dimensions and assert the Inspector's displayed metadata changes — assertion Level 1, spec S3 failure mode, `app-red` lane.
  - Reconcile the same selected entry without a revision change and assert its displayed metadata remains correct and the real Inspector reader records no additional read — assertion Levels 1 and 2, spec S5 idempotence, `app-red` lane.
  - Rename the selected file in the grid and assert the Inspector name follows the new URL — assertion Level 1, spec S5 state transition, `app-red` lane.
  - Delete the selected file and then its successor, asserting the Inspector advances to that successor and then displays an empty state — assertion Level 1, spec S2 empty boundary and S5 state transition, `app-red` lane.

## Risks & Assumptions
- The App test must show the grid throughout; a viewer test would pass through `open(..., refresh: true)` and miss this defect.
- File scans and Inspector metadata reads are asynchronous. Wait for an observed completed reconcile and metadata value, rather than relying on a fixed delay.
- Count actual metadata reads through the existing reader boundary. A count-only assertion is insufficient; pair it with Inspector name and dimensions assertions.
- The selected `FolderEntry` carries resource identifier, file size, and modification date. These are the available revision facts; unchanged selected entries should keep a stable key across unrelated watched refreshes.
- This work item has an idempotence law: replaying an unchanged snapshot does not change displayed metadata or trigger a new read (S5).
