## Unit: shared cache/pipeline pin acquisition

**Law**: Reference conservation: accepted acquisition adds exactly one reference, rejected acquisition changes no reference, and each owner releases only its own acquired reference. These are S5 state invariants, exercised across successful/rejected transition sequences rather than a property-generator dependency.

### Case: pin result reports actual atomic acquisition
- **Category**: state / failure
- **Lane**: integration (in-process real pipeline/cache, executed by package unit command)
- **Spec level**: S5 — acquire accepted pin, attempt revoked pin, release accepted pin.
- **Input**: Real ImageIOPipeline/cache/shared MemoryBudget; actual fixture pixels/key K; permit A already revoked for rejected image and a current permit B for another holder.
- **Expected output**: Successful pin returns true and count increases once. Revoked-image pin returns false; pin count, entry count and pinned/reserved budget match the preattempt snapshot. Releasing only the true acquisition restores zero pins.
- **Observable side effect**: Real cache reference count and shared budget.
- **Assertion strategy**: Level 1 / Level 3 / Level 4 — assert returned Bool together with count and MemoryBudget.Usage equality; current holder remains retrievable after rejection. A hardcoded true/false API cannot pass both branches.
- **Mock boundary**: none — real implementation.
- **Refactor that would break this**: Returning a precheck outcome detached from atomic mutation, reporting false after incrementing, or reporting true after rejection.

## Unit: Inspector transient pin lifetime

**Law**: Reader cleanup consumes exactly its own acquired reference. Rejected pin leaves every other owner's count/accounting unchanged; successful temporary acquisition returns the count to its starting value. Latest access permit governs reader success.

### Case: revocation between image return and pin preserves another holder
- **Category**: failure / state
- **Lane**: integration (package unit command)
- **Spec level**: S5 — load real image → gate before forwarded Inspector pin → retain same-key holder → revoke Inspector permit → forward rejected pin → Inspector cleanup/rejection.
- **Input**: Reader injected with a test wrapper implementing existing ImagePipeline and ImagePresentationPinning over real ImageIOPipeline. Wrapper delegates request/image normally, then pauses the Inspector pin before forwarding it. Reader's real decode yields image with permit A. Once the gate confirms image has returned and pin is pending, ensure another consumer holds K. Include the reauthorized/current-holder variant by pinning the same pixels/key using current permit B before revoking A. Release the pin gate using explicit continuations; no sleeps.
- **Expected output**: Inspector read throws CancellationError; another holder's pin count stays one, entry remains present and current B pixels remain retrievable, pinned bytes stay at baseline and staging stays zero. No cleanup unpin is issued for a false acquisition. Later explicit holder cleanup reaches zero.
- **Observable side effect**: Actual shared cache pin count, entry presence and MemoryBudget.Usage before/after reader completion.
- **Assertion strategy**: Level 1 / Level 3 / Level 4 — await cancellation and compare other-holder count, cache entry state and full pinned/reserved accounting to the saved snapshot; verify current holder pixels remain accessible and release them explicitly. Gate-call observation is only ordering support, not the behavior assertion.
- **Mock boundary**: Authorized scheduling wrapper around real pipeline/cache; no replacement cache, admission or budget. It pauses only the existing async pin boundary and forwards the real Bool result.
- **Paired integration test**: pin result reports actual atomic acquisition; existing issue194InspectorUsesSharedPipelineAndPreservesUprightThumbnail exercises actual unwrapped ImageIOPipeline/reader.
- **Refactor that would break this**: Unconditional Inspector unpin, precheck-only fix, false-success pin forwarding, or rejection that removes another holder's live entry.

### Case: accepted Inspector transient pin balances its own reference
- **Category**: success / state
- **Lane**: integration (package unit command)
- **Spec level**: S5 — parameterized starting holder count zero and one, successful Inspector acquisition/encoding/cleanup, then explicit remaining holder cleanup.
- **Input**: Same real fixture/pipeline/shared ledger and wrapper, with current Inspector permit throughout; no-holder variant and another-holder variant. For this case the wrapper must forward the real pin first, save its Bool, then pause AFTER successful acquisition but BEFORE returning to the reader. The test awaits that gate, inspects real cache/budget, then releases it by continuation.
- **Expected output**: At the post-acquisition gate, forwarded pin result is true and real cache pin count is exactly baseline + 1; pinned accounting includes the live thumbnail pixels and staging is zero. After releasing the gate, reader returns correct known metadata and usable 240 px PNG thumbnail. After reader completes, pin count equals initial count (zero or one), reserved staging is zero, and after any explicit holder cleanup pinned bytes are zero.
- **Observable side effect**: Balanced real cache pin count and ledger, plus actual PNG output.
- **Assertion strategy**: Level 1 / Level 3 / Level 4 — mandatorily assert true forwarded acquisition and real cache pinCount == baseline + 1 while the post-acquisition gate holds; assert actual live pinned bytes and zero reserved bytes. Release gate, decode returned PNG and assert dimensions, then assert pin count equals baseline and terminal pinned/reserved bytes zero. Final balance alone is insufficient: skipping both pin and unpin must fail the gated acquisition assertions.
- **Mock boundary**: Same scheduling-only wrapper forwarding real pipeline operations.
- **Paired integration test**: existing issue194InspectorUsesSharedPipelineAndPreservesUprightThumbnail and direct real pin-result case above.
- **Refactor that would break this**: Skipping acquisition entirely, skipping successful cleanup, releasing twice, rejecting all transient pins, or suppressing thumbnail output.
