  - [ ] Candidate paths are checked after resolving symlinks; no escaping path is admitted as a remapped recent.

## Risks & Assumptions
- `RecentFolderStore.add` currently deduplicates by root ID as well as URL. Remap must preserve the existing store contract while correctly handling loaded multiple descendants; avoid broad unrelated Recent Items changes.
- Roots and Recent Items are separate stores. “One step” must include a defined failure/rollback path; do not report success after only one persistence update.
- Undo snapshot must preserve complete record content and Recent Items order/timestamps, including corrupt/recovered or unsupported-version behavior where applicable.
- Trash checks must reuse actual system/per-user Trash identity logic, not merely reject every `.Trash` path.
- Explicit user selection of a Trash location follows the brief’s default: allow explicit pick; automatic opening remains forbidden. Record this interpretation in handoff.
- Rebind across volumes is permitted.
- Undo restores persisted records, recents and this window’s Lost Access state; it does not alter filesystem contents.
- Old access counters/work permits must remain invalid after rebind and Undo; restoring storage must not resurrect stale delivery authority.
- Production implementation could exceed approximately 400 lines. Proposed split boundary: WI-1 cause/automatic Trash protection; WI-2 storage transaction/remap/Undo; WI-3 native actions/strip. Notify delegator if the actual production diff crosses the brief’s threshold.
- Record one `P2-08c-T4-WI-n` RED receipt per WI using the applicable Swift/App lane, with unchanged recorded assertion files.
- All heavy jobs run serially through the specified RAM wrapper and heavy lock; no GUI tests.
- Changed-file coverage target is 100% lines/functions, preserving the accepted #284 baseline exception.
- Signed device smoke and pixel parity remain unverified by the implementer.
