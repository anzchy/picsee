## Unit: InspectorModel current-failure callback

**Law**: Only the current uncancelled selection may publish failure or invoke its callback. Clearing or changing selection permanently excludes older completions. The S5 case below checks actual temporal transitions; it makes no generated-domain claim.

### Case: CurrentFailureCallbackIsOptionalAndFollowsMappedState
- **Category**: failure
- **Lane**: unit (configured package lane)
- **Spec level**: S2/S3 — nil/present callback and permission/unreadable failure partitions.
- **Input**: Select an image with a controlled InspectorMetadataReading boundary; complete separately with noPermission and unreadable failures, callback nil and callback present; also complete with known metadata successfully.
- **Expected output**: Current failure maps to the existing noPermission/unreadable value; installed callback receives the failing selection/error on MainActor after that mapping. Nil callback does not change mapping; successful metadata remains known and does not report failure.
- **Observable side effect**: Callback observes actual current name/value and captures delivered failure identity; success has zero failure reports.
- **Assertion strategy**: Level 1/4/5 — verify mapped value/name and callback-observed state/error, alongside callback cardinality. Call count alone is insufficient.
- **Mock boundary**: Metadata I/O boundary only, paired with native InspectorOnlyPOSIXLossClearsBeforeSheet and existing InspectorMetadataReaderTests real ImageIO coverage.
- **Refactor that would break this**: Calling back before mapping, treating every successful result as failure, requiring a callback for normal mapping, or dropping selection identity.

### Case: CallbackRejectsCancelledAndSupersededFailures
- **Category**: state
- **Lane**: unit (configured package lane)
- **Spec level**: S5 — generation/cancellation exclusion invariant.
- **Input**: Hold A's metadata read; clear A then release failure. Separately hold A, select B and settle known B, then release A failure. Finally report a current B failure to show the callback is active, not disabled globally.
- **Expected output**: Cleared state remains unknown; B remains known after old A failure; no old failure callback occurs. Current B failure maps and reports once.
- **Observable side effect**: Held readers demonstrably finish without stale presentation or stale callback delivery.
- **Assertion strategy**: Level 4/5 — model name/value and callback-observed selection/state, with reader-completed evidence and zero stale reports.
- **Mock boundary**: Controlled metadata I/O paired with native StaleMetadataAndProbeNeverClearNewInput and native real Inspector read-denial case.
- **Refactor that would break this**: Moving callback outside the generation/cancellation guard or omitting guards after await.

## Unit: File Grant reader failure forwarding and scoped read probe

**Law**: A reader error causes reconnection only when current file access is actually lost. Superseded operations never change current presentation. A successful access-only probe never initiates reopening/decoding. S5 cases below cover both invariants.

### Case: InspectorOnlyPOSIXLossClearsBeforeSheet
- **Category**: failure
- **Lane**: integration (`app-red`)
- **Spec level**: S3 — real refusal during Inspector access while image remains visible.
- **Input**: Real temporary PNG with settled pixels and populated Inspector; withhold ordinary reconcile and use chmod 000 (attribute event outside vnode mask), then explicitly refresh the real Inspector reader. Confirm old pixels were still visible before that access. Restore permissions in teardown.
- **Expected output**: Inspector failure forwarding performs the scoped access probe and reaches the existing full-clear boundary before the reconnect sheet. No root or parent scope URL occurs.
- **Observable side effect**: Image remains a real existing file but unreadable; one reconnect sheet follows full presentation clearing.
- **Assertion strategy**: Level 3/4 — at willBeginSheet assert loader identity/presentation nil, neutral title, representedURL nil, Inspector name/value cleared and no image-derived AX values; assert file still exists and recorded scopes remain canonical-equivalent file URLs.
- **Mock boundary**: None for failure — real FileAccess/ImageIO/POSIX read. Timing gate delegates real header reads; scope recorder delegates real native scope.
- **Refactor that would break this**: Only forwarding folder-root failures, trusting fileExists/isReadable without an actual read, or reporting after sheet attachment.

### Case: LoaderExistingFilePOSIXLossClearsWhileReconcileHeld
- **Category**: failure
- **Lane**: integration (`app-red`)
- **Spec level**: S3 — generic loader refusal with an existing source.
- **Input**: Settled large real PNG, populated Inspector; hold reconciliation, chmod 000 without deleting the file, trigger a detail/refinement request through the real loader. Restore mode and release gate in teardown.
- **Expected output**: Loader failure forwards independently of file disappearance and held reconciliation; actual scoped read refusal triggers full clearing and one reconnect sheet. Later held work cannot restore pixels.
- **Observable side effect**: Existing unreadable source, cleared presentation, released old work.
- **Assertion strategy**: Level 3/4 — file-exists precondition, held-header proof, full before-sheet native clear and continued clearing after late release.
- **Mock boundary**: None — real filesystem and ImageIO with timing gate.
- **Refactor that would break this**: Forwarding only the missing-file branch, relying on reconcile to detect loss, or confusing loader cancellation with new read failure.

### Case: StaleMetadataAndProbeNeverClearNewInput
- **Category**: state
- **Lane**: integration (`app-red`)
- **Spec level**: S5 — access/input supersession excludes stale failure and probe completion.
- **Input**: Hold A metadata failure, openInput B and settle B, then release A failure. Separately admit A's read-failure probe while current and suspend its existing async file-access boundary. Call `openInput([B])`, which synchronously begins newer input authority, but hold B's admission at its `pipeline.request(identityRoot:)` header through an existing ImagePipeline timing decorator: ViewerInputAdmission probes there before host.openInputImage begins new access authority. Prove B admission is held and A's loader generation/identity is still unchanged. Release/allow A's denied probe to complete while B remains held. Only afterward release B admission and await settled B. Keep B readable and distinctive; add no fake production seam.
- **Expected output**: During held B admission, A's old access/loader generation is still current, but newer input alone suppresses the old denied probe: no loss sheet or presentation revocation occurs. After B admission releases, B identity/revision/title/proxy/Inspector/AX settle normally and remain B. Current real-loss cases above prove reporting is not disabled globally.
- **Observable side effect**: Both held operations complete without changing B.
- **Assertion strategy**: Level 3/4/5 — assert B's identityRoot admission gate is held, A loader generation/identity remains unchanged, and A probe completion is observed before releasing B; assert no loss sheet and no clearing at that point. Then release B and compare settled B values before/after stale metadata completion. Use meaningful read/probe completion gates rather than a sleep-only assertion. This independently kills an implementation that checks only access authority, since access changes only after B admission completes.
- **Mock boundary**: Metadata/read-probe I/O timing only; real access denial and callback mapping are paired with the two real POSIX cases above. Use existing asynchronous boundaries rather than inventing a test-only production interface.
- **Refactor that would break this**: Capturing current authority only after await, guarding access but omitting input authority while B is still being admitted, or reporting old metadata after its selection changed.

### Case: ReadableMetadataAndCorruptDecodeErrorsNeverReconnectOrLoop
- **Category**: guard
- **Lane**: integration (`app-red`)
- **Spec level**: S5 — successful access validation cannot create an automatic reopen/redecode cycle.
- **Input**: (1) Readable valid PNG with a metadata boundary that reports unreadable while the file remains actually open/readable. (2) A real readable corrupt image passed through real ImageIO producing decode failure; withhold unrelated reconciliation. Observe completed probe and pipeline requests, then a further bounded observation period with no user retry.
- **Expected output**: Metadata error stays the existing unreadable state; corrupt image stays a decode error. No reconnect alert, root lease, parent scope or new automatic open/decode request occurs after the successful access-only probe. A real scoped read succeeds in both cases.
- **Observable side effect**: Stable error state and stable completed decode/header request counts following probe completion; no retry loop.
- **Assertion strategy**: Level 3/4/5 — real successful file read, ordinary failure state, nil sheet and unchanged request counters after completion. Real corrupt fixture supplies the negative failure without faking ImageIO.
- **Mock boundary**: Metadata I/O failure only for case (1), paired with real Inspector POSIX integration and InspectorMetadataReaderTests. Case (2) uses real corrupt bytes, native access and ImageIO.
- **Refactor that would break this**: Treating every reader error as lost access or calling open/reconcile/decode again after a successful file-read probe.

### Case: PreInputReconcileCannotPublishWhileNewAdmissionIsHeld
- **Category**: guard
- **Lane**: integration (`app-red`)
- **Spec level**: S5 — reconciliation captures access and input authority at its own start; a later input excludes its publications even before access authority changes.
- **Input**: Settle A and start/hold A's real reconcile header before beginning B input. Begin `openInput([B])` and hold B at the existing identityRoot header admission gate before host.openInputImage/accessIntent changes. If an A reader-failure probe is also pending, allow it to complete and be dropped by its new-input guard. While B remains held, release A's pre-input reconcile with its real old read failure and await header/reconcile completion. Then release B admission and settle B. Separately reject/cancel a later input and trigger a fresh A/current-file foreground reconciliation to confirm no permanently latched old input stamp disables future checks.
- **Expected output**: Before B admission releases, A's loader generation and identity remain unchanged, and no sheet or clearing/reopening occurs from old A reconciliation. B then settles normally; old A work cannot invalidate B's captured admission generation. A newly started reconciliation after a rejected input remains eligible and can still detect genuine current-file loss.
- **Observable side effect**: Both held A header and B admission actually complete in the prescribed order; only B's admitted open publishes new content.
- **Assertion strategy**: Level 3/4 — prove both gates held, record A generation/identity, wait for A header/reconcile completion while B is held, then assert identical A generation/identity and no sheet. Release B and assert B's presented identity/revision/title. Follow with a fresh post-rejection genuine-loss check to exclude a permanently latched input stamp.
- **Mock boundary**: Existing ImagePipeline timing/error boundary delegates real file reads; no fake production seam. Real read-denial and normal reconciliation are paired with the POSIX cases and unchanged WI-3 reconciliation tests.
- **Refactor that would break this**: Checking only access authority in original reconciliation, capturing input authority at publication rather than reconcile start, or reusing a permanent admission stamp that prevents future foreground checks after rejected input.

### Case: FreshReaderDemandAfterRejectedInputStillDetectsLoss
- **Category**: state
- **Lane**: integration (`app-red`)
- **Spec level**: S5 — rejection preserves A's viewing state and permits future current reads, while earlier pending A operations remain excluded.
- **Input**: Settle readable A; admit unsupported/rejected input B and prove A remains displayed. In separate episodes, then deny real access to A and (1) make a genuinely new Inspector selection/refresh, (2) request a new loader detail tier. Withhold ordinary reconciliation and trigger neither foreground nor wake. Retain an old pre-B A metadata operation in a companion sequence and release it after B rejection before triggering a fresh current read.
- **Expected output**: Old pre-B results remain silent. Each new legitimate A read obtains current per-read authority, detects actual loss and fully clears before one reconnect sheet, even though A's grant was established before B. No foreground/reconcile rescue is needed.
- **Observable side effect**: A remains visible through rejected input, then a fresh reader demand alone produces full loss clearing/reconnect.
- **Assertion strategy**: Level 3/4 — prove B rejection and unchanged A identity, prove ordinary reconciliation is held, assert old callback does not alert, then assert fresh Inspector/loader demand independently clears loader/title/proxy/Inspector/AX before sheet. Meaningful reader-completion gates distinguish stale and fresh demands.
- **Mock boundary**: Existing metadata/pipeline timing boundaries only; read denial is real POSIX file I/O, paired with the two initial native POSIX cases. No Input, WindowInspectorReader or folder-root seam is introduced.
- **Refactor that would break this**: Permanently latching input authority when the File Grant opens, renewing it on old callback completion, or refreshing authority globally so a pending old read regains permission.

### Case: MissingProbePathRetainsBookmarkRenameAndTrashCompatibility
- **Category**: boundary
- **Lane**: integration (`app-red`)
- **Spec level**: S3/S5 — raw stale-path probe failure must not bypass established bookmark recovery.
- **Input**: Use existing real-bookmark/read timing support to rename A on the same volume between reader URL capture and the actual scoped open/read. Separately move it to system Trash and to an ordinary `.Trash` folder. Trigger the reader-failure forwarding path rather than relying solely on a new foreground check.
- **Expected output**: Raw missing-path errors defer to the existing bookmark re-resolution: same-volume rename/ordinary `.Trash` follow without reconnect, system Trash clears quietly, genuine missing access reconnects. No parent scan/root request occurs.
- **Observable side effect**: Real moved-file identity or quiet clearing follows established File Grant behavior.
- **Assertion strategy**: Level 3/4 — actual presented moved identity/title/proxy, absent reconnect for recovered/Trash cases, cleared presentation for Trash, canonical file-only scope history.
- **Mock boundary**: None — real files, bookmarks and ImageIO with existing timing gates; no invented port seam.
- **Refactor that would break this**: Sending every actual-read missing-path error directly to reconnect without bookmark re-resolution or classifying ordinary `.Trash` as system Trash.
